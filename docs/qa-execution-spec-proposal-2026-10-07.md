## 사람 판정 지침 부록 — **사전 등록 11-1절로 옮겼다 (2026-10-07)**

사용자 결정으로 공식 원문 인용만 남겼다: "If an object is reflected clearly in a glass window, then the reflection should be
annotated."(nuscenes-devkit `docs/instructions_nuimages.md`, Bounding Boxes 절). 이전 초안이 덧붙였던 해석(선명/흐릿 구분, 차체·물웅덩이
반사는 보류 등)은 **삭제했다** — 원문만으로 정할 수 없으면 기존 일반 규칙(망설여지면 판단 보류)을 따른다. 연습(practice1)을 이 규칙으로
다시 해석하지 않는다.

**남은 불일치(사용자 결정):** 판정 화면 지침 패널 `frontend/src/components/JudgingGuideline.tsx`에는 이전 초안의 해석이 그대로 있다
("유리창에 선명하게 비친 차는 라벨 대상 … 비친 상 위의 기존 라벨은 상자가 맞으면 오류 없음, 선명히 비친 차에 라벨이 없으면 누락 후보는
오류 있음. 흐릿하거나 차체·물웅덩이 등에 비친 모호한 상은 판단 보류"). 판정 화면은 확정 커밋 시점으로 고정되므로(5-3절) 확정 전에
원문 인용으로 맞출지 정해야 한다. 이번 작업은 프론트를 고치지 않았다.

## AI 판정 실행 설계값 제안 (2026-10-07) — 사전 등록에 아직 넣지 않았다

측정값이 아니라 **설계값**이라 여기에 제안만 둔다. 사용자가 고르면 5-4절의 해당 칸에 옮긴다. 사전 등록 5-4절에는 이 칸들이 아직
비어 있다.

| 칸 | 제안 | 이유 |
|---|---|---|
| 호출당 시간 제한 | **60초** | 그림 2장 + 짧은 JSON 응답. SDK 기본(10분)은 멈춘 호출을 너무 오래 기다린다. 드라이런에서 응답 시간 분포를 보고 줄이거나 늘린다 |
| 최대 시도 수 | **3회**(첫 시도 + 재시도 2회, 지수 대기 2·4초) | 네트워크·서버 오류(시간 초과·연결 실패·429·529·5xx)만 재시도. SDK 기본 재시도 수(2)와 같은 규모. SDK 자체 재시도는 끈다 |
| `max_tokens` | **1,024** | 답은 JSON 한 줄. 너무 낮으면 잘려 `ai_format_error`가 된다. 최대 예상 비용 계산에 이 값을 그대로 쓴다 |
| 사고(thinking) 설정 | **끔(`{"type": "disabled"}`)** | 출력 토큰·비용 변동을 줄이고 한 줄 응답 형식을 지키기 쉽다. 참고 문서상 Sonnet 5는 끔을 받는다(실제 API 미확인). 켜면 사고 토큰이 `max_tokens`를 먹어 형식 오류가 늘 수 있다 |

참고 계산(계획용, 호출 0건): 합성 20건 드라이런의 최대 예상 비용 $0.4187(상한 $1) — `experiment/planning_evidence/ai_cost_dryrun_synthetic_2026-10-07.json`.
