# `N_required` 사전 계획 — 검정력 시뮬레이션

> **이 문서는 표본 크기를 정하지 않는다.** `N_required`·`N_final`·Δ·목표 검정력은
> 전부 **미정**이고, 여기 있는 것은 그것들을 정할 때 쓸 도구와 **설계 민감도**다.

| | 상태 |
|---|---|
| `N_capacity` (시간으로 처리 가능한 양) | 계산된다 — [capacity-vs-sample-size.md](capacity-vs-sample-size.md) |
| `N_required` (Δ를 잡아내는 데 필요한 양) | **미정** |
| `N_final` (최종 검수량) | **미정** — `N_required <= N_capacity`일 때만 후보 |
| Δ | **미정** (`delta_status=undetermined`) |
| 목표 검정력 | **미정** — 0.80·0.90은 비교 예시 |
| 검정력 시뮬레이터 | 준비됨 — `experiment/evaluation/planning.py`, `experiment/power_report.py` |
| 순위 품질 가정 | **근거 없음** — 모든 결과가 민감도 전용 |

## 비전공자용 — 한 줄로

> **"두 방법의 차이가 진짜로 Δ 이상이라면, N건씩 봤을 때 그걸 알아챌 확률이
> 얼마인가"** 를 가상의 판정 기록 수천 벌로 따라가 본 것이다.

그 확률이 **검정력**이다. 검정력은 **가정에 딸린 값**이다 — "AIDA가 기준선보다
이만큼 낫다면"이라는 조건을 넣어야 나오고, 그 조건이 틀리면 숫자도 틀린다.
**시뮬레이션은 근거 없는 입력을 고쳐 주지 않는다.** 정교하게 계산해도 입력이
짐작이면 결과도 짐작이다.

## 1. 계약 — 결과를 보기 전에 고정한 것

평가 규약([evaluation-protocol.md](evaluation-protocol.md))을 그대로 따른다. 이
문서가 새로 정한 것은 없다.

| 항목 | 내용 | 근거 |
|---|---|---|
| 주 비교 | **AIDA 대 단순 IoU 불일치 기준선** (`1 − label_iou`) | 규약 2절 |
| 무엇의 효과인가 | **같은 후보 집합 안에서의 조건부 재정렬 효과** — 후보 생성까지 포함한 제품 전체 효과가 아니다 | 규약 2-1절 |
| 주지표 | 고정 검수량 N건에서 찾은 **고유 오류 수의 짝지은 차이** | 규약 3절 |
| 분석 단위 | **이미지 묶음** (같은 이미지의 후보는 독립 표본이 아니다) | 규약 8·9절 |
| 여러 데이터셋 | 데이터셋별로 계산한 뒤 **동등 가중** | 규약 8절 |
| 누락 후보 층 | **비교에서 뺀다.** 기술 통계만 | 규약 2-1절 |
| 보류 | 검수 예산을 **쓰지만** 성과로 세지 않는다 | 규약 7절 |
| 판정 규칙 | 짝지은 차이 **95% 구간 하한 > Δ** 이면 성공 | 규약 10절 |

**용어.**

- `N_required` — 정해진 Δ를 정해진 검정력으로 잡아내는 데 필요한 **데이터셋당**
  후보 수.
- `N_capacity` — 운영상 처리할 수 있는 최대치. 시간에서 나온다.
- `N_final` — `N_required <= N_capacity`가 확인된 뒤에만 후보가 되고, 사용자가
  **최종 결과를 열기 전에** 별도 커밋으로 고정한다.

**판정 규칙의 유의수준.** 양측 95% 구간의 **아래끝**만 보므로 한쪽 방향 유의수준은
α/2 = **0.025**다. 두 방법이 같을 때 "성공"이 나오는 비율이 0.05가 아니라 0.025
근처인 것이 정상이다. `alpha`는 시나리오에서 바꿀 수 없다 — 바꾸려면 규약과
`bootstrap.py`의 분위수부터 바꿔야 한다.

## 2. Δ 시나리오 — 고르지 않는다

Δ는 "이만큼은 더 찾아야 쓸모 있다"는 **사업적 최소 기준**이다. 결과를 보고 고르면
기준이 아니라 사후 설명이 된다. 그래서 **안만 늘어놓고 전부 계산한다.**

| 안 | 규칙 | N=120 | N=360 | N=600 |
|---|---|---|---|---|
| A | 데이터셋마다 고유 오류 **1건** 더 | 1 | 1 | 1 |
| B | `ceil(0.05 × N)` | 6 | 18 | 30 |
| C | `ceil(0.10 × N)` | 12 | 36 | 60 |
| D | 검수 비용·오류 누락 비용으로 환산 | **계산 불가** | | |

**비전공자용 예.** 데이터셋 3개에서 각각 120건을 검수한다고 하자.

- **A** — AIDA 순서로 봤을 때 기준선 순서보다 데이터셋마다 평균 **1개** 더
  찾으면 된다. 가장 약한 기준이다. 120건을 보는 수고에 비해 1개가 의미 있는지는
  별개 질문이다.
- **B** — 120건당 **6개** 더. 많이 볼수록 요구도 커진다.
- **C** — 120건당 **12개** 더. 오류가 드문 데이터에서는 **풀에 그만한 오류가
  없을 수 있다** — 그러면 아무리 잘 정렬해도 못 넘는다(표의 `!`).
- **D** — "후보 한 건 검수에 드는 돈"과 "오류 하나를 놓쳤을 때의 손해"가 있어야
  계산된다. **둘 다 이 저장소에 없고 지어내지 않는다.** 식은
  [pilot-evaluation-plan.md](pilot-evaluation-plan.md)의 ROI 절에 있다.

## 3. 왜 이항 검정 공식으로 계산하지 않는가

교과서 공식은 후보가 서로 **독립**이라고 가정한다. 여기서는 그렇지 않다.

- 같은 이미지의 후보가 **묶인다** — 한 이미지가 어려우면 그 안의 후보가 같이
  어렵다.
- 여러 후보가 **같은 오류**를 가리킬 수 있다 — 중복을 빼면 성과가 줄어든다.
- AIDA와 기준선이 **같은 판정을 공유**한다 — 두 방법의 결과가 서로 얽혀 있다.
- **상위 N건**만 보므로 순위가 조금 바뀌면 성과가 계단처럼 움직인다.
- 데이터셋은 크기와 무관하게 **같은 무게**다.

독립을 가정하면 표본이 실제보다 많은 척하게 되어 **필요량이 작게 나온다.**

## 4. 시뮬레이터가 하는 일과 안 하는 일

**집계 로직을 복제하지 않는다.** 복제하면 시뮬레이터가 통과시킨 설계를 실제
평가가 떨어뜨릴 수 있다.

| 시뮬레이터가 만든다 (`planning.py`) | 실제 평가 코드가 한다 (`evaluation/`) |
|---|---|
| 데이터셋·이미지·후보 | 순위·동점 처리 (`ranking.py`) |
| 오류 여부, 같은 오류를 가리키는 중복 묶음 | 예산 N 적용, 중복 제거, 보류 처리 (`summary.py`) |
| 보류 판정 | 짝지은 차이 (`paired.py`) |
| 두 방법의 점수 | 이미지 묶음 재표집·데이터셋 동등 가중 (`bootstrap.py`) |
| | 성공·불확실·실패 판정 (`verdict_against_delta`) |

한 번의 **복제**: 가상 판정 기록을 새로 만들고 → `paired_cluster_bootstrap`으로
95% 구간을 내고 → Δ 안마다 `verdict_against_delta`에 넣는다. "성공" 비율이
검정력이다. Δ 안들은 **같은 복제**를 공유한다 — 안끼리 비교할 때 잡음이 섞이지
않게.

**순위 품질**은 짝 비교 확률(AUC)로 적는다 — "오류 후보 하나와 정상 후보 하나를
골랐을 때 오류 쪽 점수가 더 높을 확률". 0.5는 무작위, 1.0은 완벽한 순위다. 내부
점수는 `U(0,1) + 강도 × [오류]`이고 `AUC = 1 − (1 − 강도)²/2`로 바꾼다.

> **정정 (2026-09-13).** 처음 시나리오에는 AIDA 강도 1.0 / 기준선 0.5를 넣었다.
> 강도 1.0은 **모든 오류를 모든 정상 후보 위에 두는 완벽한 순위**(AUC 1.0)이고,
> 기준선은 AUC 0.875였다. 숫자만 봐서는 그 가정이 안 보였고, 그대로 돌렸으면
> 검정력이 거의 모든 칸에서 높게 나왔을 것이다. 탐색 실행을 멈추고 AUC로 적도록
> 바꿨다.

## 5. 가정과 근거 — `experiment/planning_scenarios.json`

값마다 근거를 붙인다. **하나라도 `unsupported_sensitivity_example`이면 그 칸은
`official=False`** 이고 공식 결론에 못 쓴다. 파생값(예: 후보 풀에서 계산한 이미지
수)은 **가장 약한 근거**를 따른다.

| 가정 | 값 | 근거 표시 | 설명 |
|---|---|---|---|
| D | 1·2·3·4 | `business_assumption` | 사용자 결정. 비교용 |
| N | 120·240·360·480·600 | `business_assumption` | 120은 timing5 블록 크기 |
| 후보 풀 = N × 2 | 2.0 | `unsupported_sensitivity_example` | 풀이 N과 같으면 재정렬 효과가 0. 실제 풀 크기는 관측 안 함 |
| 이미지당 후보 수 분포 | 1:38, 2:10, 3:8, 4:1, 6:1 | `timing_pilot` | timing5 기존 라벨 층 92건. 177건 중 표집한 부분이라 **묶임을 과소평가**할 수 있다 |
| 오류 비율 | 0.065 | `single_reviewer_observed_hit_rate` | timing5 기존 라벨 층에서 판정자 한 명이 hit으로 고른 6/92. **참 오류 비율 아님** |
| | 0.135 | `single_reviewer_observed_hit_rate` | timing4 같은 방식 5/37. **참 오류 비율 아님** |
| | 0.25 | `unsupported_sensitivity_example` | 오류가 많은 데이터 |
| 묶임 `independent` | 몰림 0, 중복 없음 | 중복 `single_reviewer_observed_hit_rate` / 몰림 `unsupported` | 판정자가 hit으로 고른 11건이 모두 서로 다른 오류 (표본 작음) |
| 묶임 `clustered` | 몰림 0.5, 중복 1:0.6·2:0.3·3:0.1 | `unsupported_sensitivity_example` | |
| 순위 `small_gap` | AIDA 0.75 / 기준선 0.70 | `unsupported_sensitivity_example` | |
| 순위 `large_gap` | AIDA 0.85 / 기준선 0.70 | `unsupported_sensitivity_example` | |
| 보류 비율 | 0.0 | `timing_pilot` | timing1~5 판정 232건 중 보류 0 |
| α | 0.05 | `protocol_fixed` | 규약 9·10절 |
| Δ | 미정 | `business_assumption` | A·B·C를 계산만 한다 |
| 목표 검정력 | 미정 | `business_assumption` | 0.80·0.90 비교 예시 |
| 복제·재표집·씨앗 | 60 · 150 · 20260913 | `simulation_setting` | 탐색용 |

> **정정 (2026-09-13, 감사).** 위 오류 비율과 중복은 처음에 `timing_pilot`으로
> 표시했다. 판정자 한 명의 `hit` 비율을 측정된 오류 비율처럼 읽히게 하는 표시였다.
> `single_reviewer_observed_hit_rate`로 바꾸고, 이 표시가 붙으면 공식 결론에 못
> 쓰게 했다. 무엇이 결정이고 무엇이 현실인지는
> [planning-assumption-evidence.md](planning-assumption-evidence.md)에 따로 적었다.

근거 표시는 요청된 넷에 **둘을 더했고**(아래), 감사에서 판정자 hit 비율 표시를 하나 더 더했다. `protocol_fixed`(α)와
`simulation_setting`(반복 수·씨앗)은 가정이 아니다 — 넷 중 하나로 억지로 넣으면
규약 고정값이 "사업 가정"처럼, 반복 수가 "근거 없는 값"처럼 보인다. 둘은 공식
판정을 막지 않는다.

**파일럿에서 두 방법의 효과는 일부러 계산하지 않았다.** timing4·5 기록에는 AIDA
점수와 `label_iou`가 있어 계산은 가능하다. 그러나 그것을 보고 나면 Δ를 고를 때
그 숫자에 끌린다. **오류 비율(hit 비율)만** 셌고, 그것은 두 방법을 가르지 않는다.

**측정값의 한계.** hit 비율은 정답이 없는 **사람 판정**이고 판정자가 한 명이다.
anchor에서 이 판정자가 정상 라벨을 오류로 기우는 경향이 관측됐으므로
(testing-boundary.md) 실제 오류 비율보다 **높게** 잡혔을 수 있다. KITTI val의
Car 클래스, 자 하나에서 나온 값이다.

## 6. 실행

```
./experiment/venv/Scripts/python.exe experiment/power_report.py --estimate-only
./experiment/venv/Scripts/python.exe experiment/power_report.py --total-minutes 30 60 120 180 --allow-long --out <저장 경로>
```

- 먼저 **예상 소요 시간**을 찍는다. 기본 상한 30분을 넘으면 돌리지 않고,
  `--allow-long`을 붙여야 돈다. CPU만 쓴다.
- 이 기계(16코어, 작업자 15)에서 탐색 설정(복제 60·재표집 150)으로 240칸이
  약 43분으로 **추정됐고 실제로는 64.6분** 걸렸다 — 추정이 1.5배 낙관적이었다.
  원인은 작업자 수(15)로 나눈 것이다. 이 CPU는 물리 코어 10개(성능 6 + 효율 4)에
  논리 16개라, **물리 코어 수로 나누면 64.1분**으로 맞았다(같은 날 12칸 재실행도
  0.48분 대 실측 0.50분). 이제 도구가 **범위**(논리 코어 기준 ~ 물리 코어 기준)를
  찍는다. 두 번 맞았다는 것이지 보장이 아니다.
  CI 환경(`CI` 변수)에서는 `--allow-long`을 붙여도 격자를 돌리지 않는다.
  `--smoke`는 1칸·복제 5의 결정적 점검용이다.
  공식 최소(복제 200·재표집 400)로 같은 격자를 돌리면 반복만으로 약 9배라
  **대략 10시간**이다. 전체 격자가 아니라 **남은 후보 칸만** 공식 설정으로 돌리는
  것이 현실적이다(`--datasets`, `--budgets`).
- `--total-minutes`는 용량을 비교해 볼 **T 후보**이지 정한 값이 아니다.

## 7. 표 읽는 법

| 열 | 뜻 |
|---|---|
| `블록/DS`, `전체` | 그 N을 보려면 120건 블록이 데이터셋당·전체 몇 개인가 |
| `근거(DS/전체)` | `per_dataset_evidence` / `evidence` |
| `active분` | 예상 **활동 판정** 시간 (휴식·준비 제외) |
| `풀오류` | 풀에 **실제로 만들어진** 고유 오류 수(데이터셋 평균) |
| `E[AIDA]`, `E[기준]` | 복제 평균으로 각 방법이 찾은 고유 오류 수(데이터셋 평균) |
| `A`·`B`·`C` | 추정 검정력 ± 몬테카를로 표준오차 |
| `!` | Δ가 `풀오류`보다 크다 — 정렬을 아무리 잘해도 넘기 어렵다 |

**`per_dataset_evidence=observed`는 전체 계획이 관측 범위라는 뜻이 아니다.**
N=120이면 데이터셋당 1블록이라 데이터셋 기준으로는 관측 범위지만, D가 2 이상이면
"다른 데이터셋에서도 같은 속도·난이도"를 가정하므로 전체는 `extrapolated`다.

> **정정 (2026-09-13).** 처음에는 `!`를 설정값(`풀 × 오류 비율 ÷ 평균 중복`)으로
> 표시했다. 그런데 중복 묶음은 **같은 이미지 안에서만** 생기고 이미지 대부분이
> 후보 1건이라, 설정한 중복이 **일부만** 만들어진다 — 탐색 격자에서 설정대로면
> 고유 오류가 33% 줄어야 했는데 실제로는 3~9%만 줄었다. 그래서 실제 고유 오류는
> 설정값보다 많다. 표시를 시뮬레이션이 실제로 만든 수로 바꾸고 손계산 검사를 붙였다.

## 8. 탐색 결과 (2026-09-13)

> **읽기 전에.** 아래는 **근거 없는 순위 품질 가정**에 딸린 탐색 결과다. 240칸
> 전부 `official=False`, 전부 `too_few_iterations`(복제 60 · 재표집 150,
> 몬테카를로 표준오차 최대 ±0.065)다. **어떤 칸도 권고가 아니고 `N_required`가
> 아니다.** 전체 표는 [power-sensitivity-2026-09-13.md](power-sensitivity-2026-09-13.md).

실행: 240칸, 작업자 15, **64.6분** (추정 43분 — 추정이 1.5배 낙관적이었다).

**기계가 읽는 원본**: `experiment/planning_evidence/power_grid_explore_2026-09-13.json`·`.csv`·`.manifest.json` — 코드 커밋, 시나리오 SHA-256, 칸 씨앗, 반복 수, 소요 시간, 출력 해시.
모든 행에 `exploratory=true`, `official_iteration_requirement_met=false`가 붙어 있다.
같은 씨앗으로 D1·N120 12칸을 다시 돌려 원본과 0건 차이를 확인했다.

> **감사에서 고친 표시.** 표의 `0.00±0.00`·`1.00±0.00`은 과신이다 — 표준오차
> `sqrt(p(1−p)/R)`는 p가 0·1이면 0이 된다. 복제 60에서 0/60의 95% Wilson 상한은
> **0.06**이다. 원본 CSV·JSON에 Wilson 구간을 붙였고, 이제 도구는 0·1일 때 한계를
> 찍는다. 아래 요약의 "0.80 이상 칸 수"는 점추정 기준이다.

### 순위 품질 차이가 작으면(AUC 0.75 대 0.70) 어느 칸도 0.80 예시에 안 닿았다

| Δ 안 | 0.80 이상 칸 | 0.90 이상 칸 |
|---|---|---|
| A (1건) | 0 / 120 | 0 / 120 |
| B (5%) | 0 / 120 | 0 / 120 |
| C (10%) | 0 / 120 | 0 / 120 |

가장 높은 칸은 Δ A에서 **0.77 ± 0.05** (D4 · N600 · 오류 비율 0.25)다. **효과가
없어서가 아니다** — 같은 조건의 세상 한 벌을 따로 확인하니 AIDA가 데이터셋당
평균 15건 더 찾았는데 95% 구간이 [5.3, 24.6]으로 폭이 19였다. D=1이면 폭이 36까지
벌어져, 따로 본 세상 두 벌 중 하나는 0을 걸쳤다. **차이가 작으면 이미지 묶음 재표집의 구간이 넓어서 한 번의
평가로 가르기 어렵다**는 뜻이다.

### 차이가 크면(AUC 0.85 대 0.70) Δ 안에 따라 갈렸다

| Δ 안 | 0.80 이상 칸 | 0.90 이상 칸 |
|---|---|---|
| A (1건) | 99 / 120 | 88 / 120 |
| B (5%) | 13 / 120 — 전부 오류 비율 0.25 | 6 / 120 |
| C (10%) | 0 / 120 | 0 / 120 |

**Δ B·C는 N에 비례해 커지는데, 풀의 고유 오류도 대략 `오류 비율 × 2N`뿐이다.**
오류 비율 0.065면 풀 오류가 약 0.13N이고 C는 0.10N을 요구한다 — 두 방법 차이가
풀 오류의 대부분이어야 한다. 표의 `!`(Δ > 풀 오류)는 **한 칸도 안 걸렸지만**
그것은 필요조건일 뿐이라, 걸리지 않았다고 달성 가능하다는 뜻이 아니다.

### 데이터셋당 120건(관측 범위)에서

`per_dataset_evidence=observed`인 칸은 N=120뿐이다. 그 칸에서 0.80 예시에 닿은
경우:

| 순위 차이 | 오류 비율 | Δ A가 0.80 이상인 D | Δ B · C |
|---|---|---|---|
| AUC 0.75 / 0.70 | 전부 | 없음 | 없음 |
| AUC 0.85 / 0.70 | 0.065 | 없음 | 없음 |
| AUC 0.85 / 0.70 | 0.135 | D ≥ 3 | 없음 |
| AUC 0.85 / 0.70 | 0.25 | D ≥ 2 | 없음 |

D ≥ 2이면 전체는 `extrapolated`다. 이 표는 "관측 범위 운영안으로 무엇을 잡을 수
있을 **수도** 있는가"를 가정별로 보여줄 뿐이다.

### 그 밖에 보인 것

- **D가 커지면 같은 N에서 검정력이 오른다** — 데이터셋별 차이를 평균하면 흔들림이
  줄어든다. 대신 총 검수량(`N × D`)과 전체 블록 수가 늘어 용량·근거 범위가 나빠진다.
- **묶임(`clustered`)은 대부분의 칸에서 차이가 작았지만, Δ가 경계에 걸린 칸에서는
  컸다.** 평균 차이는 0.02였으나 360칸 중 17칸이 0.15 이상 벌어졌고, 전부 오류 비율
  0.25 · AUC 0.85/0.70 · Δ B였다. 예: D4 · N360에서 0.97 → 0.63, D2 · N480에서
  0.83 → 0.50. **평균만 보고 "묶임이 중요하지 않다"로 읽으면 안 된다.**
- 설정한 중복(오류 하나에 평균 후보 1.5건)은 이미지당 후보가 적어 **일부만**
  실현됐다 — 풀의 고유 오류가 3~9%만 줄었다(설정대로면 33%). 더 강한 묶임에서는
  차이가 더 클 수 있고, 이 격자는 그것을 시험하지 않았다.

  > **정정 (2026-09-13, 같은 날).** 처음에는 이 항목을 "`clustered`와 `independent`의
  > 차이가 작았다 … 설정한 중복이 거의 실현되지 않았다"로 적었다. 평균만 봤고, 실현
  > 정도를 재지 않고 짐작했다. 칸별 차이와 풀 오류 수를 다시 세고 고쳤다.
- 용량(활동 판정 시간 후보별로 `N_capacity < N`인 조합):
  - T=30분: D1·N≥360, D2·N≥240, D3·전부, D4·전부
  - T=60분: D2·N≥360, D3·N≥240, D4·N≥240
  - T=120분: D3·N≥480, D4·N≥360
  - T=180분: D4·N600

- **순위 품질이 근거 없음이다.** 그래서 모든 칸이 `official=False`다. 검정력이
  높게 나온 칸도 "AIDA가 그만큼 낫다면"이라는 조건부 숫자다.
- **개발 데이터에서 짐작한 분포는 최종 자연 오류 분포를 보장하지 않는다.**
- **판정자 한 명의 파일럿은 신규·외부 사용자를 대표하지 않는다.** 오류 비율과
  `s_plan` 둘 다 그 한 사람에게서 나왔다.
- **관측한 120건 블록 1회는 여러 번 반복한 블록을 검증하지 않는다.** 용량 열의
  `extrapolated`·`strongly_extrapolated`가 그 뜻이다.
- **복제 60은 공식 최소에 못 미친다.** 모든 칸이 `too_few_iterations`이고, 표준오차가
  최대 ±0.065까지 간다. 0.78과 0.82를 가르지 못한다.
- **이 표로 `N_required`를 정하지 않는다.** 유리한 칸 하나를 골라 권고하지도 않는다.
- **두 방법의 점수 잡음을 서로 독립으로 만든다.** 실제 AIDA와 IoU 기준선은 같은
  예측에서 나와 강하게 얽혀 있을 것이다. 독립이면 짝지은 차이의 흔들림이 커져
  **같은 AUC 차이에서 검정력이 낮게** 나오는 쪽이다. 보정하지 않았다 — 상관을

## 10. `N_final`까지 남은 결정

**최종 결과를 열기 전에**, 아래를 사용자가 정하고 별도 커밋으로 고정해야
`N_final`이 생긴다.

**사용자가 정할 것 — 결정**

1. **D** — 최종 평가 데이터셋 수
2. **T** — 활동 판정 시간 상한
3. **Δ** — A·B·C·D 중 하나와 근거
4. **검정력 또는 구간 폭 방침** — 목표 검정력(예: 0.80 또는 0.90)

**사용자가 고르지 않는 것 — 현실에 대한 값.** 추정하거나 근거 없음으로 남긴다.

- 참 오류 비율 — 지금은 판정자 hit 비율(약함)뿐
- AIDA와 기준선의 순위 품질, 그리고 **그 차이** — AIDA는 주입 개발 조건 AUC(약함),
  기준선과 차이는 근거 없음
- 이미지 내 묶임·한 오류당 중복 후보 — 제한적·약함
- 보류와 판정 오류 — 제한적·근거 없음

> **정정 (2026-09-13, 감사).** 처음 이 절에는 "순위 품질 가정의 근거 — 없으면 가장
> 보수적인 안으로 계산하겠다는 결정"을 사용자 결정 목록에 넣었다. 순위 품질은
> 고르는 값이 아니다. 근거 없음이면 여러 값을 민감도로 보여 줄 뿐이고, 공식
> 반복으로 돌려도 그 칸은 `official=False`다.
> [planning-assumption-evidence.md](planning-assumption-evidence.md)

그 뒤 **해당 칸만** 공식 반복(복제 200 이상·재표집 400 이상)으로 돌려
`N_required`를 내고, `N_required <= N_capacity`와 근거 범위를 확인한다.
안 맞으면 시간이 아니라 **설계**(D·Δ·데이터 선택)를 고친다.

>    약 0.507이 만들어졌다(0.9를 넣어도 0.507). 이제 거부한다. 탐색 격자의 조합
>    (최대 0.25 · 0.5)은 실현 가능해서 결과에 영향이 없다 — 실측 0.253.

계산하는지**를 볼 뿐, 입력한 오류 비율·순위 품질이 현실인지는 보지 않는다.
