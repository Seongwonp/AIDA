# 13. PPT용 그래프·다이어그램 체크리스트
<!-- 시점 표시 -->

> **끝난 일의 기록이다.** 2026 국방기술 창업경진대회는 2026-08-19에 2차 예선에서 탈락했고, 그 뒤로 프로젝트는 발표 준비가 아니라 기술 검증으로 방향을 바꿨다. 이 문서는 **당시 상태 그대로 두며 갱신하지 않는다** — 지금 시스템과 다른 것이 정상이다. 현재 상태는 저장소 README와 [21-next-plan.md](./21-next-plan.md)를 볼 것.


CUDA 데스크탑에서 13개 조건 전체를 동일 50epoch로 재실행 중이다(진행 상황은
[09-getting-started.md](./09-getting-started.md) 참고). 이 문서는 그 결과가 나왔을 때
PPT(`../AIDA_발표자료_v2(결과반영).pptx`)에 반영할 시각자료를 무엇을, 어떤 데이터로,
왜 넣어야 하는지 미리 정리해 둔 것이다. 실험이 끝나면 이 목록대로 하나씩 만들면 된다.

## 데이터 소스

- `backend/app/data/metrics.csv` — 13개 조건 × (map50, map50_95, precision, recall)
- `experiment/iou_table.csv` — 조건별 magnitude → 평균 IoU / IoU 감소율
  (`experiment/compute_iou_table.py`로 생성, 학습 완료와 무관하게 GT 라벨만 있으면 계산 가능)
- 기존 `docs/assets/experiment-results-priority1.png` — 핵심 7개 조건짜리 구버전,
  13개 전체 결과로 교체 필요

## 우선순위순 체크리스트

### 1. [필수] 13개 조건 전체 성능 저하 막대그래프 — mAP@0.5 기준

- **왜**: 기존 `experiment-results-priority1.png`는 7개 조건만 있고 epoch도
  불일치(clean 50 vs 나머지 25)했다. 재실행 결과는 13개 전체가 동일 50epoch라
  이 한계가 사라진다 — 2차 예선 배점 "해결방안 및 MVP 구현 가능성"(25점)을
  가장 직접적으로 뒷받침하는 그래프.
- **형태**: 가로축 = 13개 조건(clean 기준선 포함), 세로축 = clean 대비 mAP@0.5
  저하율(%). 유형별(가로/세로/회전)로 색 구분, magnitude 크기순 정렬.
- **대체용**: `backend/app/data/metrics.csv` 전체 13행이 실측으로 채워지면
  프론트엔드 `PerformanceChart.tsx`를 그대로 스크린샷해도 됨(코드 이미 구현됨).

### 2. [필수] Precision vs Recall 비교 그래프

- **왜**: [12-experiment-results.md](./12-experiment-results.md) 핵심 발견 3 —
  "라벨 오류는 오탐이 아니라 미탐을 늘린다"는 것이 진단 로직(`/api/diagnose`)의
  핵심 근거. 이 비대칭을 시각적으로 보여주면 "왜 mAP만이 아니라 Recall을
  보는가"라는 심사위원 질문에 선제 대응 가능.
- **형태**: 그룹 막대그래프, 가로축 = 13개 조건, 세로축 = Precision/Recall
  각각의 clean 대비 변화율(%p). Precision은 거의 0 근처, Recall만 확연히
  떨어지는 대비가 보이게.

### 3. [신규·필수] 조건별 IoU 감소율 — magnitude 대비 오류 강도 검증표

- **왜**: 김성호 교수님 피드백 3번([11-professor-feedback.md](./11-professor-feedback.md)) —
  "단순 길이 증감(%)보다 IoU 감소량 기준이 더 설득력 있다"는 지적에 대한
  직접 대응. 재학습 없이 `experiment/compute_iou_table.py`로 바로 계산 가능.
- **형태**: 표 또는 선 그래프. 가로축 = magnitude(%또는 도), 세로축 = 평균
  IoU(또는 IoU 감소율 %). width/height/rotation 세 선으로 구분. "magnitude가
  커질수록 IoU가 어떻게 떨어지는가"를 보여줘, 뒤이어 나오는 성능 저하 그래프와
  나란히 배치하면 "오류 강도(IoU) → 성능 저하"라는 인과 스토리가 완성됨.
- **주의**: `compute_iou_table.py`는 GT 전체 박스에 변형을 그대로 적용한
  이론적 IoU다(실제 학습엔 30%만 반영됨, `config.ERROR_RATIO`). 슬라이드
  각주에 "이론적 최대 왜곡 기준" 정도로 명시할 것 — 학습 결과 그래프의
  "30%만 오류 주입" 조건과 숫자가 다른 이유를 심사위원이 헷갈리지 않게.

### 4. [필수] 회전각 오류 한계 설명 다이어그램

- **왜**: 교수님 피드백 2번(★ 가장 중요) — 회전각 오류가 "방향과 무관하게
  박스가 커지는" 현상으로 나타나는 기하학적 이유. 심사위원이 물어볼 가능성이
  높아 선점하는 슬라이드가 이미 계획돼 있음([12-experiment-results.md](./12-experiment-results.md)
  "핵심 발견 2").
- **형태**: 3단 비교 다이어그램 — (1) 원본 박스, (2) 박스를 실제로 15도
  회전시킨 모습(사각형이 기울어짐), (3) 축정렬 재계산 후 결과(기울어진 박스를
  감싸는 더 큰 정사각형에 가까운 박스). "왜 항상 커지는가"가 한 장에 보이게.
  코드 구현은 `experiment/error_injector.py`의 `apply_rotation()`.
- **후속 로드맵 화살표**: 이 다이어그램 옆에 "본선 전 검토: OBB 도입 또는
  중심점이동·스케일 교체"를 작은 화살표/각주로 추가(피드백 문서의 대응 방향
  그대로).

### 5. [필수] ROI 정량화 슬라이드

- **왜**: 교수님 피드백 6~7번 — "발주처가 실제로 비용을 지불하게 만들려면
  ROI를 숫자로 보여줘야 한다."
- **형태**: 좌우 비교 카드 또는 막대그래프. "수작업 전수 재검수 비용" vs
  "AIDA로 의심 구간만 재검수했을 때 비용" 두 값을 나란히.
- **숫자 출처**: 사업계획서(신청서 자료)에 이미 있는 벤치마크 활용 —
  바운딩박스 라벨링 단가 객체당 $0.02~0.04(공개 벤치마크 기준), 이미지 10만장
  ×평균 5객체(=50만개 박스) 전수 재검수 시 약 1~2만 달러. 여기에 AIDA가
  "재검수 우선순위 높음"으로 좁혀주는 비율(예: 오류 조건 3종 중 실제 라벨의
  30%만 오류라는 실험 조건 자체가 근거)을 곱해 절감액을 계산. **정확한 절감률은
  아직 확정 수치가 아니므로 "예시" 또는 "추정" 명시 필수** — 사업계획서도
  "실제 비용절감률은 MVP 실증을 통해 검증할 계획"이라고 못박아둔 부분과
  모순되지 않게 톤 맞출 것.

### 6. [있으면 좋음] 전체 파이프라인 다이어그램 (PPT용 재구성)

- **왜**: "MVP 구현 가능성"을 한 장으로 설명하는 개요도. README에 이미
  mermaid로 있는 걸 PPT 슬라이드 디자인 톤(흑백+형광 최소화)에 맞게 재구성만
  하면 됨 — 새로 설계할 필요 없음.
- **원본**: [README.md](../README.md) "전체 데이터 흐름" mermaid 다이어그램
  (KITTI → 전처리 → 오류 라벨 생성 → 학습·평가 → metrics.csv → API → 대시보드).

### 7. [있으면 좋음] 대시보드 실제 화면 스크린샷

- **왜**: "구현 가능성" 배점에서 목업이 아니라 실제로 동작하는 화면이라는
  증거. 이미 로컬에서 `npm run dev`로 확인 가능한 상태.
- **캡처 대상**: 품질 점수 카드, 조건별 성능 저하 그래프(위 1번과 동일 데이터가
  화면에 그대로 나옴), 오류 유형 진단 표(교수님 피드백 반영한 새 문구
  "오류 유형 확률 진단 · 재검수 우선순위 가이드" 포함된 버전).

## 만드는 순서 제안

1. CUDA 실행 완료 대기 → `metrics.csv` 13행 전부 실측으로 갱신 확인
2. `python experiment/compute_iou_table.py` 실행 → `iou_table.csv` 확보
3. 위 1~3번(막대그래프, Precision/Recall, IoU표)을 먼저 만든다 — 전부 CSV
   두 개만 있으면 바로 그릴 수 있고, 배점이 가장 큰 항목이다
4. 4~5번(회전각 다이어그램, ROI 슬라이드)은 손으로 그리거나 사업계획서 숫자
   재정리가 필요해 시간이 더 든다 — 시간 되면 우선순위대로
5. 6~7번은 기존 자료 재활용이라 마지막에 여유 있으면
