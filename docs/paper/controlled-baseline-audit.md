# 통제 실험 기준선 사전 조사 — 2026-10-01

조사 기준: `d9ee1f3`. 노트북의 추적된 코드·저장 결과를 읽었다. 실제 데스크탑 캐시·가중치 존재와 과거 실행 환경은 확인하지 않았다. 새 점수 계산, 추론, 재학습, 판정, val 접근은 하지 않았다.

## 1. 결론

현재 저장된 집계 결과만으로 7시드 실험에 무작위·IoU·ObjectLab 기준선을 완성할 수 없다. 그렇다고 재학습이 필요하다고 판정할 근거도 없다. 데스크탑에서 상세 캐시를 확인하고, 부족하면 기존 자 가중치로 재추론하는 순서다.

`--reuse-cache`는 모든 기준선에 필요한 예측 캐시를 뜻하지 않는다. 채점된 AIDA finding의 제한된 필드로 심각도를 다시 계산하는 경로다. 또한 현재 새 추론과 캐시 재사용의 정렬 규칙이 달라, 기존 수치 재현을 먼저 검증해야 한다.

## 2. 평가 단위와 정답

| 항목 | 현재 코드에서 확인한 정의 | 기준선 설계에 미치는 영향 |
|---|---|---|
| 진단 대상 | `evaluate_box_accuracy.score_condition`은 조건별 `images/train`, `labels/train`을 진단하며 `limit` 적용 | 모델 성능 측정용 평가 분할과 구별한다. 논문의 평가 이미지 수를 진단 모집단 크기로 그대로 사용하지 않는다 |
| 정밀도 단위 | `verdicts_by_rank`의 finding 한 건 | 고유 라벨 오류 수와 다르다. 같은 객체에 여러 finding이 있으면 중복 계수 가능 |
| 기존 라벨 정답 | `injection_record.json`의 `errored`와 출력 라벨 인덱스 대조 | 이미지와 라벨 인덱스가 없으면 전체 라벨 정답을 재구성할 수 없다 |
| 중복 주입 | 중복 출력 인덱스와 그 직전 원본 인덱스를 모두 해당 오류로 인정 | 고유 오류 단위로 바꾸면 기존 점수와 다른 지표가 된다 |
| 누락 정답 | 삭제 박스와 예측 후보의 IoU가 0.4 이상이면 매칭 | 기존 라벨과 같은 모집단이 아니다. 전체 라벨 기준선으로 누락을 직접 평가할 수 없다 |
| 회수율 | 맞힌 주입 인덱스를 집합으로 모아 `caught` 계산 | finding별 TP와 분자가 다르다 |
| 상위 10% | 조건별 finding 수의 10%를 내림하고 최소 1건, 실제 선택 건수로 정밀도 계산 | 방법별 후보 수의 10%를 각각 쓰면 공통 고정 예산 비교가 아니다 |
| 조건 평균 | `evaluate_box_accuracy.main`은 빈 목록의 0도 포함; `compare_rulers_seeded.measure`는 빈 목록을 `silent`로 빼고 평균 | 두 산출물의 평균을 같은 분모로 간주하지 않는다 |

근거: [채점 코드](../../experiment/evaluate_box_accuracy.py), [시드 비교](../../experiment/compare_rulers_seeded.py), [순위 정의](../../experiment/label_diagnosis.py).

## 3. 저장 자료의 범위

| 자료 | 남은 정보 | 없는 정보 / 주의 |
|---|---|---|
| `seeded_ruler4_7seeds.json`, `seeded_coco_3seeds.json` | 조건·시드·limit, 자별 집계, 조건별 P@10%·적합도 등 | 개별 후보 ID·박스·IoU·예측 전체가 없다. 집계 재확인은 가능하나 새 순위 계산은 불가 |
| `box_accuracy_eval.json` | TP/FP·주입 수·조건별 집계·기존 정밀도 | `verdicts_by_rank`는 요약 저장에서 제외된다 |
| 별도 `box_accuracy_verdicts*.json` 형식 | 정답 여부, 의심 유형, 심각도, 지배 유형 여부, raw signal, confidence, class ID | 이미지·라벨 ID·박스·label_iou·전체 예측이 없다. raw signal을 모든 유형의 IoU로 간주할 수 없다. 해당 실제 파일은 추적 파일 목록에서 확인되지 않음 |
| 진단 population 출력 | `collect_population=True`일 때 전체 라벨·미매칭 예측·ObjectLab 점수를 구성 가능 | 일반 `score_condition`은 이 옵션을 켜지 않는다. population 출력이 raw prediction 전체 캐시라는 뜻은 아니다 |

`compare_rulers_seeded.measure`는 `score_condition`을 직접 호출한다. 별도 verdict 캐시를 저장하는 main을 거치지 않으므로, 시드 결과가 있다는 사실만으로 상세 캐시가 있다고 판단할 수 없다. 캐시 이름의 `_tag()`는 모델 상위 폴더 이름을 사용하며 실행 시드·설정 전체를 식별하는 manifest가 아니다. 서로 다른 실행을 구별할 수 있는지 실제 파일에서 확인해야 한다.

추적 파일 조회에서 실제 `best.pt`·`injection_record.json`·verdict 캐시를 찾지 못했다. 이는 데스크탑의 git 밖 자료가 없다는 뜻이 아니다.

## 4. 기준선별 실행 가능성

| 비교 | 노트북에서 지금 가능 | 데스크탑에서 필요한 최소 정보 | 없을 때 다음 단계 |
|---|---|---|---|
| 기존 집계 재확인 | 저장된 조건별 값·시드별 값 재집계 | 과거 manifest는 별도 확인 | 재학습 불필요 |
| AIDA finding 안 무작위 순서 | TP와 finding 수가 보존된 조건은 기대 정밀도 TP/flagged를 산술적으로 구할 수 있음. 7시드 전체 비교가 확보된 것은 아님 | 조건·자·시드별 finding 정답, 실제 k, 빈 조건 처리 | 기존 자 재추론으로 finding 복원 |
| AIDA 후보 안 IoU 재정렬 | 현재 집계·verdict tuple만으로 불가 | 동일 후보의 ID·IoU·정답·동점 규칙 | 기존 자 재추론 |
| 전체 기존 라벨 무작위·IoU | 불가 | 전체 라벨 ID·주입 정답·IoU, 동일 범위와 공통 예산 | 원본 라벨·주입 기록 복원; IoU 부족 시 기존 자 재추론 |
| ObjectLab 박스 적응 | 불가 | 이미지별 라벨 박스·클래스 및 예측 박스·클래스·신뢰도, 또는 출처 검증된 동일 정의 점수 | 기존 자 재추론 후 점수 산출 |
| 누락 층 비교 | 기존 라벨 지표에 합칠 수 없음 | 미매칭 예측 모집단·삭제 박스·매칭 규칙 | 별도 층과 예산을 명세한 뒤 실행 |

무작위 기대값 TP/flagged는 해당 finding 풀에 조건부인 값이다. 전체 라벨 무작위 기준선이나 오류 주입률과 같지 않으며, 그 평균만으로 불확실성 구간까지 얻는 것은 아니다.

재학습은 필요한 가중치가 없고 복구할 수도 없는 경우에 검토한다. 통제 조건마다 학습한 모든 가중치가 항상 필요한 것은 아니다. clean 자 비교는 해당 자·시드의 가중치가 필요하고, self 비교는 조건별 가중치가 필요하다.

## 5. 구현 전에 해결할 점

1. **캐시 재사용 순위 불일치:** 새 추론의 `review_order`는 `(계통 유형 여부, -severity)`로 정렬하지만 `load_cached_rows`의 기본 경로는 `-severity`만 사용한다. 코드 경로 차이는 확인했고, 과거 결과에 미친 크기는 확인하지 않았다. 수정 시 별도 회귀 검사와 과거 결과 보존이 필요하다.
2. **두 질문 분리:** AIDA finding 풀 안 재정렬은 순위 효과, 전체 라벨 비교는 후보 생성까지 포함한 효과다. 기존 94%에 기준선 숫자만 붙이면 같은 질문이라는 보장이 없다.
3. **공통 예산:** 전체 라벨 비교의 k를 방법별 후보 수에서 따로 산출하지 않는다. 후보 부족·동점·빈 조건 처리도 먼저 정의한다.
4. **고유 라벨 대 finding:** 동일 라벨의 여러 유형을 합칠지, 누락 층을 분리할지 정한다. 변경된 지표는 기존 결과 재현과 나란히 구분한다.
5. **ObjectLab 범위:** 박스 점수 적응으로 명시한다. Car 단일 클래스에서 swap이 퇴화한다는 설명을 다중 클래스 통제 실험 전체에 적용하지 않는다.
6. **과거 실행 추적:** 현재 코드만으로 과거 실행 설정을 확정하지 않는다. 커밋, 자 해시, 이미지 목록, 클래스 매핑, limit, 추론 문턱·NMS, 라이브러리 버전과 주입 기록을 대조한다.

## 6. 다음 작업과 완료 조건

### 노트북

1. 이 조사로 평가 단위·캐시 요구사항을 공유한다 — 완료.
2. 데스크탑 목록을 받은 뒤 기준선 명세를 작성한다. 동일 후보 재정렬과 전체 라벨 비교 중 어떤 표를 만들지, 층·정답·중복·k·시드·집계를 명시한다.
3. 코드 구현 시 작은 합성 자료로 중복·누락·동점·빈 조건·캐시 재현을 검사한다. 실제 결과 생성은 필요한 자료를 확보한 뒤 진행한다.

### 데스크탑 인수인계

먼저 **읽기 전용 목록 조사**만 한다. 기존 결과를 덮어쓰지 말고 val을 열지 않는다.

- 비교 대상 결과 파일별 조건·자·시드·limit와 과거 실행 명령/커밋을 찾는다.
- `box_accuracy_verdicts*.json`, 상세 진단 JSON, prediction 캐시의 파일 수·필드명·행 수를 기록한다. JSON 파일명만 보고 사용 가능 판정을 내리지 않는다.
- 이미지 ID, 라벨 인덱스, 좌표, 예측 클래스·신뢰도, IoU, 주입 정답 중 어떤 필드가 실제로 있는지 표로 돌려준다.
- 조건별 `injection_record.json`과 라벨·이미지 목록의 대응을 확인한다.
- 필요한 clean 자/시드 및 self 조건별 가중치 존재·해시를 확인한다. 로컬 절대 경로는 공개 문서에 싣지 않는다.
- 각 비교를 **캐시로 계산 / 기존 가중치 재추론 / 자료 복구 필요 / 재학습 검토**로 분류한다. 이 단계에서는 실행하지 않는다.

회신 완료 조건: 비교 대상마다 입력 출처와 누락 필드를 적고, 재추론 필요 여부가 판단 가능해야 한다. 사용자 연습 판정 20~60건 및 교수 검토 준비는 이 조사와 독립적으로 진행할 수 있다.

## 7. 이번 작업의 경계

새 실험 결과가 없으므로 논문 근거표의 수치·초안 주장을 갱신하지 않았다. 사전 등록 확정, 판정 상한, 투고처 결정도 이번 조사에서 하지 않았다. 실제 캐시의 사용 가능성은 데스크탑 확인 후 확정한다.
