# 기록 단위 부트스트랩의 미판정 후보 — 회귀 검사·합성 시뮬레이션·추가 판정량 (2026-09-27)

> **분석 방식도 사전 등록도 여기서 정하지 않는다.** 문제를 검사로 고정하고, 실제 규칙에 맞춘
> 합성 시뮬레이션으로 크기 감을 보고, 고정된 재표본에서 필요한 판정 범위를 세는 도구를 더했다.
> val은 열지 않았다. 배경은 [`literature-review-2026-09-27.md`](literature-review-2026-09-27.md) §3.3과

## 1. 문제 (저장소 코드로 확인, 회귀 검사로 고정)

| 경로 | 코드 | 검사 |
|---|---|---|
| 원래 방법별 상위 N 합집합 ∪ 무작위 K만 판정한다 | `evaluation.py judge_ids` | 기존 |
| 기록을 재표집하면 원래 N 밖의 후보가 상위 N에 든다 | `bootstrap.iter_resamples` → `top_n` | `test_재표집은_원래_상위_N_밖의_후보를_상위_N에_올린다` |
| 그 후보가 미판정이면 예산에는 들고 수확에는 0으로 센다 | `summary.summarise` (`in_budget` 대 `judged`) | `test_미판정_후보는_예산은_쓰고_수확은_0으로_세어진다` |
| 부트스트랩이 그 수를 보고한다(처리는 안 바꿈) | `paired_cluster_bootstrap["unjudged_in_top_n"]` | `test_부트스트랩은_상위_N의_미판정_수를_보고한다` |

원래 표본의 점 추정치(두 방법 상위 N 전부 판정)는 영향이 없다. 영향은 **구간**에만 들어간다.

## 2. 합성 시뮬레이션 — 실제 규칙에 맞춤

`experiment/sim_unjudged.py` → `planning_evidence/sim_unjudged_2026-09-27.json` (`synthetic: true`).
원본 스크립트와의 차이: 동점 키 `sha256("{tie_seed}:{후보 id}")`(백엔드와 같은 식, 검사로 고정), 무작위 K는
**AIDA 규칙 밖 라벨**에서, 방법은 **aida(v2)·all_label_iou·all_label_objectlab 셋**의 상위 N 합집합 ∪ K, 차이 부호는
**기준선 − aida**(D7). N=90, K=50, 부트스트랩 씨앗 42·2000회, 기록 35개, 라벨 약 1,100개.

| 씨앗 | 라벨 | 판정 범위 | iou−aida 관측 | 현재 코드 구간 | 전량 판정(oracle) 구간 | objectlab−aida 현재 / oracle | 재표본당 상위 90 중 미판정 평균 (aida / iou / ol) |
|---|---|---|---|---|---|---|---|
| 1 | 1,195 | 242 | +3 | [−5, 11] | [−5, 8] | [−29, 2] / [−29, 0] | 2.51 / 0.45 / 1.93 |
| 2 | 1,080 | 245 | 0 | [−7, 5] | [−6, 5] | [−13, 14] / [−12, 12] | 1.31 / 0.54 / 2.61 |
| 3 | 1,059 | 233 | −1 | [−6, 7] | [−7, 6] | [−14, 7] / [−15, 7] | 1.09 / 0.21 / 2.41 |

**읽는 법.** 미판정 진입은 재표본의 43~50%에서 생기고 방법마다 비대칭이다(aida·objectlab 쪽이 iou보다
많다). 구간 끝이 1~3건 움직이며 방향은 씨앗마다 다르다. **이 숫자는 합성 조건의 예시이고 실제 데이터의 값이
아니다.** "몇 건 이동"을 근거로 인용하지 않는다.

## 3. 고정된 재표본에서 필요한 상위 N 후보의 합집합 — `evaluation.coverage`

부트스트랩 씨앗·반복 수·동점 씨앗이 사전에 고정돼 있으면 **어느 후보가 어느 재표본의 상위 N에 드는지는 판정 전에
전부 계산할 수 있다** — 순위만 필요하고 판정은 필요 없다. `resample_top_n_union`이 `iter_resamples`(부트스트랩과
**같은 생성기**, 같은 난수 순서 — 검사로 고정)를 돌려 방법별 합집합과 원래 판정 범위 밖의 추가분을 센다.

| 씨앗 | 원래 판정 범위 | 필요 합집합 ∪ K | **추가 판정량** | aida 합집합 (원래 90) | iou | objectlab | 반복 100/500/1000/2000에서의 aida 합집합 |
|---|---|---|---|---|---|---|---|
| 1 | 242 | 295 | **+53** | 120 | 127 | 121 | 111 / 115 / 117 / 120 |
| 2 | 245 | 306 | **+61** | 146 | 141 | 129 | 119 / 133 / 140 / 146 |
| 3 | 233 | 304 | **+71** | 141 | 138 | 142 | 125 / 141 / 141 / 141 |

이 합성 조건에서는 원래 판정 범위의 **약 22~30%**를 더 판정하면 고정된 2000개 재표본 어디에서도 미판정 후보가
상위 N에 들지 않는다. 합집합은 반복 수에 따라 계속 늘어나므로(위 곡선) **반복 수를 먼저 고정해야 목록이
닫힌다.** 실제 nuImages 묶음에서는 얼린 뒤 같은 함수로 다시 센다 — 그 값은 실행 기록에 적는다.

**이 방식이 하는 것과 안 하는 것.**

- 한다: 고정된 재표본 계산에서 미판정 후보를 없앤다. 미판정을 0으로 세지도, 재표본을 버리지도 않는다.
- 안 한다: 신뢰구간의 통계적 타당성을 보장하지 않는다. 기록 수가 적을 때 백분위 구간의 포함률, 재표본에서
  검수량(`in_budget`)이 달라지는 문제, 추정 대상이 무엇인지의 정의는 별개다. 판정 대상이 순위 의존적으로 늘어나므로
  "무작위 K 표본"의 뜻도 바뀌지 않는지 확인해야 한다(K는 여전히 규칙 밖 라벨의 단순 무작위 표본이고 합집합과 겹치면
  한 번만 판정한다).

## 4. 열려 있는 선택 (정하지 않았다)

| 안 | 무엇 | 이 문서가 준 것 |
|---|---|---|
| (a) 합집합 전부 판정 | 위 3절. 추가 판정량은 실제 묶음에서 재계산 | 계산 도구·합성 크기 감 |
| (b) condensed list | 판정된 풀 안에서만 순위 | 추정 대상이 바뀐다 — 미구현 |
| (c) 고정 목록 부트스트랩 | 원래 상위 N 목록 고정, 기록만 재표집 | 재선정 효과를 못 말한다 — 미구현 |
| (d) 대치·민감도 | 미판정을 K 표본 오류율로 대치 | 미구현 |

**"하한 구간"으로 이름만 바꾸는 안은 채택하지 않는다** — 각 방법의 수확은 낮게 잡힐 수 있어도 두 방법
차이의 하한이 되지는 않는다(Codex 검토). 사전 등록 확정과 val 개봉은 이 선택이 끝날 때까지 보류한다.

## 6. 안 (a) 실행 명세와 연결 구현 (2026-09-27 밤, Codex 추천 반영 — 확정 아님)

### 6.1 두 숫자를 가른다

| 이름 | 무엇 | 바뀌는가 |
|---|---|---|
| **비교 예산 N = 90** | 방법별 상위 N. 점 추정치와 1차 지표의 검수량 | 안 바뀐다 |
| **연구용 총 판정량** | 상위 N 합집합 ∪ 무작위 K ∪ **고정 재표본 추가 후보** | 묶음을 얼린 뒤 정해진다. 실행 기록에 적는다 |

추가 후보는 **부트스트랩 계산용**이다. 어느 방법의 원래 상위 N도, 점 추정치도 바꾸지 않는다(검사
`test_추가_후보는_판정_목록에_들고_N과_원래_상위_N은_그대로다`). 내보내기의 `judging`이 두 숫자를 따로 적는다.

### 6.2 연결 구현

| 단계 | 구현 | 보장 |
|---|---|---|
| 계산 | `POST .../evaluations`에 `coverage_iterations`·`coverage_seed` → `compute_bootstrap_coverage` | **최종 분석과 같은 길**(`export_for_aggregation` → `importer.load_export` → `coverage.resample_top_n_union`)이라 모집단·기록 묶음·순위·동점 키가 분석과 같다. 미판정 후보도 모집단에 그대로 있다 |
| 고정 | `snapshot.bootstrap_coverage`(반복 수·씨앗·방법·입력 지문·추가 id 목록)가 **묶음 지문에 든다** | 본 판정 전에 목록이 닫힌다. 바꾸면 지문이 바뀌어 판정이 붙지 않는다 |
| 판정 목록 | `judge_ids`가 추가 후보를 포함 → 화면(`queue`)·저장 검증·내보내기 모두 같은 집합 | 추가 후보가 화면에서 빠지거나 저장이 거부되지 않는다(연결 검사) |
| K 표본 | `random_sample` 표시·분모 그대로. 추가 후보는 `coverage_extra=true`로 따로 표시 | K와 합쳐지지 않는다 |
| AI 보조 30% | **확장된 최종 판정 목록**에서 추출(`auxiliary_sample.pool`에 명시) | 일치도는 "최종 판정 목록 전체(원래 상위 N + K + 추가 후보 혼합)에서의 사람–보조 일치"를 대표한다. 원래 상위 N만의 일치도가 아니다(`represents`) |
| 최종 분석 | `paired_cluster_bootstrap(require_judged_top_n=True)` | 어느 재표본의 상위 N에라도 `verdict=None`이 있으면 구간을 내지 않는다. `hold`는 완료된 판정이라 통과 |
| 확인 | 합성 자료: 확장 목록만 판정 = 전량 판정, **모든 재표본에서** 같은 차이 (`test_coverage_analysis_link.py`, `test_bootstrap_coverage.py`) | — |

### 6.3 감당하기 어려울 때 — 판정 전에 정하는 중단·재계획 절차

1. 묶음을 얼리기 **전에** 판정 상한 C(건)를 실행 계획에 적는다(시간 파일럿 `s_plan` 5.02초 × 계획 세션 수).
2. 묶음을 얼린 뒤 `judging.total_judging_list`가 C를 넘으면 **그 묶음으로 본 판정을 시작하지 않는다.** 얼린 묶음과
   수치는 실행 기록에 남기고 지우지 않는다.
3. **하지 않는 것:** 결과(어느 후보가 추가됐는지)를 본 뒤 씨앗·반복 수를 바꾸기, 추가 후보를 임의로 잘라내기,
   미판정을 0으로 세거나 재표본을 버리기.
4. **하는 것:** 사전 등록을 **개정**(N·반복 수·표본 이미지 수·방법 수 중 무엇을 줄일지와 이유)하고 커밋한 뒤, **새
   평가 ID**로 다시 얼린다. 개정 전후 묶음 지문을 둘 다 기록한다. 개정은 판정 전이므로 결과에 맞춘 것이 아니다.

### 6.4 이 방식이 보장하는 것과 하지 않는 것

고정 재표본의 판정 누락을 없앤다. 신뢰구간의 포함률·통계적 타당성은 검증하지 않았고 보장하지 않는다.
사전 등록 확정과 val 개봉은 여전히 보류다.
