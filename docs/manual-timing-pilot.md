# 수동 시간 측정 파일럿 — 사람이 직접 판정하는 절차

> **이 자료는 시간 추정용이고 효능 증거가 아니다.**
>
> 여기서 나오는 것은 "후보 하나에 사람이 얼마나 걸리는가"뿐이다. AIDA가
> 기준선보다 나은지는 **여기서 알 수 없고, 알려고 해서도 안 된다.**
>
> 작성 2026-09-09.

## 왜 사람이 해야 하는가

지금까지의 dry pilot은 **자동 클릭**이었다. 후보당 2~4초가 나왔고 그걸로 N을
계산하면 800이 넘는다 — 사람이 클릭 속도로 검수한다는 가정이다.

N은 시간 상한을 후보당 시간으로 나눈 값이라, **분모가 틀리면 N 전체가 틀린다.**
그 분모는 사람이 실제로 박스를 들여다본 시간이어야 한다.

## 하지 않는 것

| 금지 | 왜 |
|---|---|
| 최종 평가용 데이터 사용 | 쓰는 순간 그 데이터는 개발 데이터가 된다 |
| 성과 비교 내보내기 열람 | 결과를 보고 기준을 고르게 된다 |
| 이 자료를 최종 평가에 재사용 | 같은 이유 |
| 이 결과로 Δ 선택 | Δ는 사업적 최소 기준이지 관측값이 아니다 |
| "자연 오류 검증"이라고 부르기 | 판정자가 개발자다 |

**개발용 임시 데이터셋만 쓴다.** 사용자가 이미 올려 둔 데이터셋은 건드리지
않는다.

## 준비

서버 두 개를 띄운다.

```bash
cd backend && ./venv/Scripts/python.exe -m uvicorn app.main:app --port 8000
```

```bash
cd frontend && npm run dev
```

임시 데이터셋과 평가 묶음은 준비 스크립트가 만든다.

```bash
./experiment/venv/Scripts/python.exe experiment/make_timing_pilot.py
```

이 스크립트는 **후보 목록과 평가 id를 만들고 판정할 주소를 찍어 준다.**
판정은 하지 않는다.

## 판정 방법

1. 찍힌 주소를 브라우저에서 연다.
2. **평소 속도로** 판정한다. 빨리 하려고도, 정성껏 하려고도 하지 않는다 —
   재려는 것은 평소의 속도다.
3. `hit`(오류였다) / `miss`(오류 아니었다) / `hold`(모르겠다) 중 고른다.
   **모르겠으면 `hold`를 누른다.** 억지로 결정하면 시간도 판정도 왜곡된다.
4. 누락 후보는 "어느 객체인가"까지 정한다. 같은 객체를 두 후보가 가리키면
   **이미 만든 것에 잇는다.**

### 최소 두 세션으로 나눈다

재표집 단위가 세션이라 **세션이 하나면 구간을 만들 수 없다.** 한 번에 다
하지 말고 중간에 창을 닫았다가 다시 연다.

| | 권장 |
|---|---|
| 후보 수 | 20~30건 (최소 10건) |
| 세션 수 | 2~3개 (최소 2개) |
| 한 세션 길이 | 10~15분 |

### 중간에 자리를 비울 때

**그냥 비우면 된다.** 60초를 넘긴 구간은 활동 시간에서 빠진다. 탭을 다른 데로
옮기거나 창을 내려도 그 시간은 안 세어진다.

**창을 닫고 나가도 된다.** 닫히는 순간 기록이 마저 전송되고, 실패하면
브라우저에 남았다가 다음에 다시 간다.

### 언제 멈추는가

- 목표 후보 수를 채웠을 때
- 집중이 떨어져 "평소 속도"가 아니게 될 때 — **그 세션은 거기서 끝낸다**
- 저장 실패가 반복될 때 — 도구 문제이므로 멈추고 기록을 남긴다

## 끝난 뒤

```bash
./experiment/venv/Scripts/python.exe experiment/timing_report.py \
    --dataset <dataset_id> --evaluation <evaluation_id>
```

나오는 것:

```
timing_usable            이 기록으로 시간을 재도 되는가
complete_sessions        끝을 본 세션 수
judged_candidates        판정을 끝낸 후보 수
mean_seconds             후보당 평균
s_plan_seconds           N 계획용 보수적 상한
p75_seconds              후보 난이도 분포 (계획값이 아니다)
```

### `timing_usable`이 거짓이면

**N을 계산하지 않는다.** 이유가 함께 나온다.

| 이유 | 무엇을 하나 |
|---|---|
| 온전한 세션이 모자람 | 세션을 더 한다 |
| 판정한 후보가 모자람 | 후보를 더 본다 |
| 중복 이벤트 | 재전송이 겹친 것이다. 기록을 보고 원인을 찾는다 |
| 빠진 순번 | **전송이 유실됐다.** 그 구간의 시간은 복구할 수 없다 |

최소 기준(세션 2개, 후보 10건)은 **근거가 약한 운영 기준**이다. 통계적으로
유도한 값이 아니라 "이보다 적으면 평균의 구간이 아무것도 말하지 않는다"는
짐작이다.

## 무엇이 어디에 남는가

```
uploads/<dataset_id>/evaluations/<evaluation_id>/
  snapshot.json        얼린 후보 목록 (판정 대상)
  adjudications.json   판정 결과
  activity.jsonl       작업 기록 원본  ← 시간의 근거
```

**셋 다 보존한다.** `activity.jsonl`이 원본이고 요약은 언제든 다시 만들 수
있다 — 규칙이 바뀌면 다시 계산한다.

실행 명세(`experiment/run_manifest.py`)는 이 파일럿에 필요 없다. 모델을
돌리지 않기 때문이다.

## 이 다음

1. `timing_usable`이 참인 기록에서 `s_plan`을 얻는다.
2. 사용자가 `D`(최종 데이터셋 수)와 `T`(전체 활동 시간 상한)를 정한다.
3. `N = floor((T / D) / s_plan)`을 계산한다.
4. 사용자가 Δ를 **사업적 최소 기준으로** 고른다.
5. **최종 평가 결과를 열기 전에** 별도 커밋으로 셋을 고정한다.

절차의 근거는 [pilot-evaluation-plan.md](pilot-evaluation-plan.md)에 있다.
