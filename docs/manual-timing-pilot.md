# 수동 시간 측정 파일럿 — 사람이 직접 판정하는 절차

> **이 자료는 시간 추정용이고 효능 증거가 아니다.**
>
> 여기서 나오는 것은 "후보 하나에 사람이 얼마나 걸리는가"뿐이다. AIDA가
> 기준선보다 나은지는 **여기서 알 수 없고, 알려고 해서도 안 된다.**
>
> 작성 2026-09-09.

## 왜 사람이 해야 하는가

지금까지의 dry pilot은 **자동 클릭**이었다. 후보당 2~4초가 나왔고 그걸로 N을
계산하면 800이 넘는다 — 사람이 클릭 속도로 검수한다는 가정이다.

N은 시간 상한을 후보당 시간으로 나눈 값이라, **분모가 틀리면 N 전체가 틀린다.**
그 분모는 사람이 실제로 박스를 들여다본 시간이어야 한다.

> **2026-09-09 정정 — 첫 파일럿은 판정이 불가능한 화면이었다.**
>
> `make_timing_pilot.py`가 1픽셀 회색 PNG를 늘려 쓰고 박스도 난수로 만들었다.
> 주석에는 "미리보기가 무엇을 그리는지는 이 파일럿의 관심이 아니다"라고 적어
> 두었는데 **그게 틀렸다.** 판정 시간은 곧 이미지를 보는 시간이다. 볼 것이
> 없으면 전부 "모르겠다"가 되고, 그렇게 나온 값은 판정 시간이 아니라 버튼
> 클릭 시간이다.
>
> 지금은 **개발 데이터의 실제 이미지**를 쓰고, 후보는 실제 라벨에 오류를
> 주입해 만든다.

## 자료의 출처

| | |
|---|---|
| 이미지·라벨 | `experiment/data/processed/{images,labels_gt}/val` — 이미 내려받아 둔 **개발 데이터**(KITTI 기반 파이프라인) |
| 새로 내려받는 것 | **없다.** 이 스크립트는 있는 것만 쓴다 |
| 최종 평가 제외 | **이미 제외돼 있다.** 이 분할은 AIDA를 만들며 쓴 개발 데이터이고, 최종 평가는 "미사용 이미지"로 한다(docs/25 3단계) |
| 라이선스 | **원문을 이 작업에서 확인하지 않았다.** 저장소 안에서 개발용으로 이미 쓰던 자료를 그대로 쓴다. 외부에 이미지를 싣거나 배포하지 않는다 |

**후보는 AIDA의 예측이 아니다.** 자를 돌리지 않고 `error_injector.py`로 실제
라벨에 오류를 주입해 만든다.

| 후보 | 만드는 법 | 판정자가 보게 되는 것 |
|---|---|---|
| 틀린 기존 라벨 | 박스를 40% 늘리거나 35% 줄이거나 30% 옮긴다 | 박스가 객체를 못 감싼다 |
| 멀쩡한 기존 라벨 | 원래 라벨 그대로 | 잘 감싸고 있다 |
| 누락 | 라벨을 **빼고** 그 자리를 가리킨다 | 객체가 있는데 라벨이 없다 |

멀쩡한 라벨을 섞는 이유는 **"오류 아니었다"가 실제로 나올 수 있어야** 하기
때문이다. 전부 진짜 오류면 판정이 아니라 확인 작업이 된다.

정답은 `pilot_answer_key.json`에 따로 있다. **판정 전에 열지 않는다** — 보고
나면 그 판정은 가림이 아니다.

## 하지 않는 것

| 금지 | 왜 |
|---|---|
| 최종 평가용 데이터 사용 | 쓰는 순간 그 데이터는 개발 데이터가 된다 |
| 성과 비교 내보내기 열람 | 결과를 보고 기준을 고르게 된다 |
| 이 자료를 최종 평가에 재사용 | 같은 이유 |
| 이 결과로 Δ 선택 | Δ는 사업적 최소 기준이지 관측값이 아니다 |
| "자연 오류 검증"이라고 부르기 | 판정자가 개발자다 |

**개발용 임시 데이터셋만 쓴다.** 사용자가 이미 올려 둔 데이터셋은 건드리지
않는다.

## 무엇을 보고 무엇을 판단하는가

화면에는 이미지 한 장이 넓게 잘려 나오고 박스가 두 색으로 그려진다.

| 색 | 뜻 |
|---|---|
| **빨강 실선** | 지금 판정하는 **기존 라벨** |
| **빨강 점선** | **빠졌다고 지목된 자리** (여기 라벨이 없다) |
| **파랑** | 이 이미지에 **이미 붙어 있는 다른 라벨** |

클래스 이름도 함께 나온다. **가리는 것은 방법·점수·원래 순위·세부 의심
유형**이지, 무엇을 보는 작업인지가 아니다 — 그것까지 숨기면 판정할 수 없다.

### 기존 라벨 검수 — 이 박스가 그 객체를 잘 감쌌는가

| 누를 것 | 언제 |
|---|---|
| **오류였다** | 박스가 객체를 **명백히** 못 맞췄다. 크게 넘치거나 모자라거나, 옆으로 밀렸거나, 아예 다른 것을 감쌌다 |
| **오류 아니었다** | 실무상 **고칠 필요가 없다.** 경계가 몇 픽셀 어긋나도 이대로 쓰면 된다 |
| **모르겠다** | 경계가 애매하거나, 가려서·너무 작아서 객체를 확인할 수 없다 |

예를 들면 이렇다.

- 차 한 대를 감싸야 하는데 **차 두 대를 함께** 감쌌다 → 오류였다
- 박스가 차 뒤쪽 절반만 덮고 앞부분이 **박스 밖으로 나가 있다** → 오류였다
- 박스가 차보다 **눈에 띄게 크게** 잡혀 도로와 배경이 많이 들어왔다 → 오류였다
- 범퍼 끝이 **2~3픽셀** 잘렸다 → 오류 아니었다
- 멀리 있어 뭉개진 물체라 차인지 확신할 수 없다 → 모르겠다

### 누락 검수 — 그 자리에 라벨돼야 할 객체가 있는가

| 누를 것 | 언제 |
|---|---|
| **오류였다** | 점선 자리에 **실제 객체가 있는데** 라벨(파랑)이 없다 |
| **오류 아니었다** | 객체가 아니거나, 라벨 대상이 아니다. **이미 파랑 박스가 덮고 있다면** 누락이 아니다 |
| **모르겠다** | 가림·해상도 때문에 객체인지 확인할 수 없다 |

**오류였다**를 골랐으면 "어느 객체인가"까지 정한다. 같은 이미지에서 **같은
객체**를 두 후보가 가리키면 **이미 만든 `M1`에 잇고**, 다른 객체면 **새
객체**를 만든다. 안 이으면 한 오류가 둘로 세어진다.

### 경계가 조금 어긋난 것 — **기준을 결과 전에 정한다**

**임의의 IoU 숫자를 만들지 않는다.** "IoU 0.7 미만이면 오류"라고 적으면
그럴듯해 보이지만 근거가 없고, 사람이 화면에서 IoU를 잴 수도 없다.

대신 이렇게 정한다.

> **"이 라벨을 이대로 학습에 쓸 것인가, 아니면 고쳐야 하는가."**
>
> 고칠 만하면 `오류였다`, 이대로 써도 되면 `오류 아니었다`.

이 기준은 사람마다 조금씩 다르게 적용된다. **그래서 `모르겠다`가 있다** —
"고쳐야 하나 말아야 하나"를 두고 망설이게 되면 억지로 정하지 말고 `모르겠다`를
누른다. 억지로 결정하면 시간도 판정도 왜곡된다.

**이 문단은 판정을 시작하기 전에 고정한 것이다.** 결과를 보고 고치지 않는다.

## 판정 방법

1. 찍힌 주소를 브라우저에서 연다.
2. **평소 속도로** 판정한다. 빨리 하려고도, 정성껏 하려고도 하지 않는다 —
   재려는 것은 평소의 속도다.
3. 위 기준대로 세 버튼 중 하나를 고른다.
4. 이미지가 안 뜨면 그 후보는 **판정하지 말고 넘어간다.** 안 보이는 것을
   "오류 아니었다"로 누르면 그건 판정이 아니다.

### 최소 두 세션으로 나눈다

재표집 단위가 세션이라 **세션이 하나면 구간을 만들 수 없다.** 한 번에 다
하지 말고 중간에 창을 닫았다가 다시 연다.

**다시 열면 아직 판정하지 않은 첫 후보에서 이어진다.** 이미 판정한 것을 넘기는
시간이 그 후보들의 판정 시간에 다시 쌓이면 안 되기 때문이다. 되돌아보고 싶으면
"이전"이나 "처음부터 다시 보기"를 누르면 되고, **그때의 시간은 의도한 재검토라
정상적으로 기록된다.**

#### 이 두 세션이 무엇이 아닌가

**같은 판정자의 반복 작업 블록이지 독립 사용자 표본이 아니다.**

| | |
|---|---|
| 재는 것 | **이 개발자가** 이 도구로 후보 하나를 판정하는 데 걸리는 시간 |
| 재지 않는 것 | 다른 사람의 속도, 숙련되지 않은 사람의 속도, 모집단 평균 |

세션 단위 부트스트랩 상한(`s_plan`)은 **이 개발자의 운영시간 계획용
휴리스틱**이다. 세션이 서로 독립인 관측이라는 가정 자체가 약하다 — 같은 사람이
같은 날 연달아 한 작업이라 두 번째 세션은 첫 번째에 익숙해진 상태다.

**외부 사용자 속도나 모집단 일반화의 근거로 쓰지 않는다.** 이 값으로 정하는
것은 "우리가 최종 평가에 몇 건을 배정할 수 있는가"뿐이다.

| | 권장 |
|---|---|
| 후보 수 | 20~30건 (최소 10건) |
| 세션 수 | 2~3개 (최소 2개) |
| 한 세션 길이 | 10~15분 |

### 중간에 자리를 비울 때

**그냥 비우면 된다.** 60초를 넘긴 구간은 활동 시간에서 빠진다. 탭을 다른 데로
옮기거나 창을 내려도 그 시간은 안 세어진다.

**창을 닫고 나가도 된다.** 닫히는 순간 기록이 마저 전송되고, 실패하면
브라우저에 남았다가 다음에 다시 간다.

### 언제 멈추는가

- 목표 후보 수를 채웠을 때
- 집중이 떨어져 "평소 속도"가 아니게 될 때 — **그 세션은 거기서 끝낸다**
- 저장 실패가 반복될 때 — 도구 문제이므로 멈추고 기록을 남긴다

## 끝난 뒤

```bash
./experiment/venv/Scripts/python.exe experiment/timing_report.py \
    --dataset <dataset_id> --evaluation <evaluation_id>
```

나오는 것:

```
timing_usable            이 기록으로 시간을 재도 되는가
complete_sessions        끝을 본 세션 수
judged_candidates        판정을 끝낸 후보 수
mean_seconds             후보당 평균
s_plan_seconds           N 계획용 보수적 상한
p75_seconds              후보 난이도 분포 (계획값이 아니다)
```

### 사람이 판정한 기록으로 안 보이면

`implausible_for_human_judging`이 나오고 **N을 계산하지 않는다.**

| 신호 | 뜻 |
|---|---|
| 후보당 중앙값 2초 미만 | 자동 클릭으로 잰 시간일 수 있다 |
| 보류 90% 초과 | 화면을 안 보고 눌렀거나, 판정할 수 없는 자료였다 |
| 열기만 하고 판정 없음 | 시간만 흘렀다 |

이 기준도 **근거가 약한 운영 기준**이다. 넘겼다고 사람이 한 것이 증명되지는
않는다 — **못 한 것만 걸러낸다.**

### `timing_usable`이 거짓이면

**N을 계산하지 않는다.** 이유가 함께 나온다.

| 이유 | 무엇을 하나 |
|---|---|
| 온전한 세션이 모자람 | 세션을 더 한다 |
| 판정한 후보가 모자람 | 후보를 더 본다 |
| 중복 이벤트 | 재전송이 겹친 것이다. 기록을 보고 원인을 찾는다 |
| 빠진 순번 | **전송이 유실됐다.** 그 구간의 시간은 복구할 수 없다 |

최소 기준(세션 2개, 후보 10건)은 **근거가 약한 운영 기준**이다. 통계적으로
유도한 값이 아니라 "이보다 적으면 평균의 구간이 아무것도 말하지 않는다"는
짐작이다.

## 무엇이 어디에 남는가

```
uploads/<dataset_id>/evaluations/<evaluation_id>/
  snapshot.json        얼린 후보 목록 (판정 대상)
  adjudications.json   판정 결과
  activity.jsonl       작업 기록 원본  ← 시간의 근거
```

데이터셋 자리에는 이것도 있다.

```
uploads/<dataset_id>/
  images/              개발 데이터에서 복사한 실제 이미지
  labels/              오류가 주입된 라벨 (화면이 문맥으로 그린다)
  classes.txt
  label_diagnosis.json 후보 목록
  pilot_answer_key.json  ← **판정 전에 열지 않는다**
```

**셋 다 보존한다.** `activity.jsonl`이 원본이고 요약은 언제든 다시 만들 수
있다 — 규칙이 바뀌면 다시 계산한다.

실행 명세(`experiment/run_manifest.py`)는 이 파일럿에 필요 없다. 모델을
돌리지 않기 때문이다.

## 이 다음

1. `timing_usable`이 참인 기록에서 `s_plan`을 얻는다.
2. 사용자가 `D`(최종 데이터셋 수)와 `T`(전체 활동 시간 상한)를 정한다.
3. `N = floor((T / D) / s_plan)`을 계산한다. **이 N은 이 개발자가 그 시간 안에
   볼 수 있는 양이지, 일반 사용자의 처리량이 아니다.**
4. 사용자가 Δ를 **사업적 최소 기준으로** 고른다.
5. **최종 평가 결과를 열기 전에** 별도 커밋으로 셋을 고정한다.

절차의 근거는 [pilot-evaluation-plan.md](pilot-evaluation-plan.md)에 있다.
