# 다음 평가 제안 — 손대지 않은 데이터셋에서 (실행하지 않음)

> **제안서다. 아무것도 실행하지 않았고 데이터셋을 고르지 않았다.** N·Δ·`N_required`·`N_final`,
> 1차 지표, 씨앗은 여기서 정하지 않는다 — 판정 전에 커밋하는 사전 등록에서 사용자가 정한다.
> 배경은 [adr-ranking-separation.md](adr-ranking-separation.md), 데이터 경계는
> [evaluation-data.md](evaluation-data.md).

## 1. prelim1이 답하지 못한 질문

| 질문 | prelim1 | 다음 평가에서 필요한 것 |
|---|---|---|
| **v1 대 v2 — AIDA 후보 안의 기존 라벨 순서** | 없음 (v2는 prelim1 뒤에 만들었다) | 두 순서를 같은 후보 묶음에 얼리고 상위 N 합집합을 판정 |
| **후보 생성** — AIDA 규칙이 놓친 오류가 얼마나 되나 | 평가 안 됨. 판정은 두 순서 상위 90의 합집합뿐 | AIDA 후보에 **없는** 라벨까지 포함한 무작위 표본 판정 |
| **순진한 전체 라벨 IoU 검수와 비교** | 없음. 기준선도 AIDA 후보 안에서만 줄 세웠다 | 모든 라벨을 `1 − IoU`로 줄 세운 방법을 따로 두고 상위 N을 판정 |
| **누락 후보** | 24건 중 22건 오류(개발자 1인), 비교군 없음 | 별도 층 기술 통계. 비교군은 아직 정의되지 않았다 |
| **판정의 일관성** | 판정자 1인 | 가능하면 둘째 판정자 또는 외부 판정자, 일부 표본 이중 판정 |

**주의 — v2와 IoU 기준선은 AIDA 후보 안에서 같은 순서다.** v2의 기존 라벨 순서가
`1 − label_iou`라서, prelim1식 "AIDA 후보 안 v2 대 IoU 기준선"은 같은 순서끼리 견준다. 다음
평가의 비교는 **v1 대 v2**(후보 안 재정렬)와 **AIDA 후보 생성 + 순서 대 전체 라벨 IoU**
(후보 생성까지)로 나눠야 의미가 있다.

## 2. 설계 틀 (값은 비워 둔다)

### 방법

| ID | 후보 집합 | 순서 | 지금 코드 |
|---|---|---|---|
| `aida_v1_systematic_boost` | AIDA 규칙이 만든 후보 | 계통 유형 먼저 | 있음 |
| `aida_v2_candidate_iou` | AIDA 규칙이 만든 후보 | 층마다 후보 신호 | 있음 (시험) |
| `all_label_iou` (가칭) | **모든 기존 라벨** | `1 − (가장 많이 겹치는 예측과의 IoU)` | **없음** |

### 판정 대상

- 층마다 방법별 상위 **N** 합집합 — 겹친 후보는 한 번만 판정한다(prelim1과 같은 규칙).
- 후보 생성을 재려면 **모든 라벨 중 무작위 K개**를 따로 판정한다. 합집합에 든 라벨과 겹치면 한
  번만 판정하고, 무작위 표본에서 뽑혔다는 사실은 따로 기록한다.
- N·K·씨앗은 사전 등록에서 정한다. 판정량 상한은 `(기존 라벨 층 방법 수) × N + (누락 층) N + K`다.

### 분석 틀

- 기존 라벨 층: 검수량 N에서 방법별 **고유 오류 수**와 짝지은 차이, 이미지 묶음 짝지은 부트스트랩.
- 연속 프레임이 있는 데이터(주행 영상)는 **장면 묶음(`group_id`)**을 재표집 단위로 한다 — 묶음
  규칙은 판정 전에 고정한다.
- 무작위 표본: AIDA 후보 밖 라벨의 판정 오류 비율과 구간(후보 생성이 놓친 비율의 추정).
- 누락 층: 기술 통계만.
- 판정자가 둘 이상이면 이중 판정 표본에서 일치도를 내고, 불일치 조정 절차를 **판정 전에** 정한다
  (지금은 설계되지 않았다 — [evaluation-adjudication-design.md](evaluation-adjudication-design.md)).

### 지금 없어서 만들어야 하는 것

1. 한 평가 묶음에 **AIDA 순서 두 벌(v1·v2)**을 얼리는 기능 — 지금 묶음은 순위 버전 하나만 담는다.
2. `all_label_iou` 후보(모든 라벨)와 무작위 라벨 표본 층.
3. 판정자 ID와 이중 판정 저장.
4. `group_id` 채우기(지금 내보내기는 늘 비어 있다).

## 4. 쓰지 않는 데이터

- prelim1의 300장(KITTI val) — 소비된 개발 데이터
- 시간 파일럿 이미지(KITTI 파생)
- KITTI 2D object 학습 데이터 — 자를 학습했다. 나머지 KITTI 과제도 구성상 겹친다
- COCO val2017 Car 520장 — COCO 자 학습과 벤치마크에 썼다. `yolov8n.pt` 사전학습 때문에 COCO
  train2017도 사실상 본 데이터로 본다(공식 출처로 확인하지 않았다)
- 최종 평가 데이터 — 개발/최종 경계 결정이 커밋되기 전에는 쓰지 않는다

## 5. 풀리지 않은 법·데이터 위험

1. **자의 학습 데이터 자체가 비상업이다.** KITTI는 CC BY-NC-SA 3.0이다. 평가 데이터를 깨끗하게
   골라도 KITTI로 학습한 자를 B2B 제품에 쓸 수 있는지는 따로 법률 검토가 필요하다.
2. **B2B 제품을 위한 내부 평가가 "상업 목적"인지** — BDD100K·nuImages·Waymo·Cityscapes에 걸린다.
3. **Flickr 출처 이미지의 권리** — Open Images·Objects365·VOC는 주석 라이선스가 이미지를 덮지 않는다.
4. **원문을 못 읽은 것** — nuScenes/nuImages 약관, IDD, VOC 주석 라이선스, BDD100K 가입 요건.
5. **COCO 중복 검사가 불완전하다** — 겹침 도구가 자르기·뒤집기를 못 잡는다
   ([evaluation-data.md](evaluation-data.md)).
6. **클래스 정의 차이** — Van 없음(BDD100K·Waymo·VOC), Car 대신 Vehicle(Waymo), Cyclist 파생
   (BDD100K·nuImages·Open Images). Car 한 클래스로 좁히면 대부분 피하지만 Waymo는 남는다.
7. **파생 상자는 "자연 라벨"이라는 주장을 약하게 한다** — Cityscapes 차량, Argoverse.
8. **연속 프레임** — 장면 묶음·중복 제거 규칙을 사전 등록에 넣어야 한다.
9. **약관은 바뀐다** — 고른 뒤 다시 확인한다.

## 6. 사용자가 정할 것 (이 순서로)

1. 법률 검토 범위 — 자(KITTI) 사용과 평가 데이터의 "상업 목적" 해석.
2. 그 결과로 남는 후보 중 데이터셋 하나와 개발/최종 경계.
3. 이 제안의 질문 중 1차 비교 하나(v1 대 v2, 또는 후보 생성 포함 비교).
4. 그 뒤에 구현(2절 목록)과 사전 등록(N·K·씨앗·Δ 방침·판정자) — 판정 전에 커밋.
