# 03. 기술 검증 실험 설계서

## 1. 목적

가상(공개 데이터셋 기반) 참값에 오류 바운딩박스를 주입했을 때, **오류 유형별로
서로 구분되는 객체탐지 성능 저하 패턴이 실제로 나타나는지** 검증한다. 이를 실제
데이터셋 성능과 비교해 오류 유형을 역진단할 수 있는지가 최종 목표다.

## 2. 데이터 범위

| 항목 | 내용 |
|---|---|
| 데이터셋 | KITTI Object Detection (2D) |
| 확보 경로 | cvlibs.net/datasets/kitti 원본, 또는 Roboflow Universe의 YOLO 포맷 변환본 |
| 대상 클래스 | Car 단일 클래스 (Van, Truck, Pedestrian 등 제외, DontCare 영역 별도 처리) |
| 학습셋 | 300~500장 |
| 평가셋 | 100~150장 (원본 라벨 유지, 모든 조건에서 공통 사용) |
| 참값(GT) | KITTI 원본 라벨을 참값으로 재사용 (신규 이미지 생성 없음) |

## 3. 시스템 파이프라인 (4단계)

```
01. 가상 이미지와 참값 생성   → 공개 데이터셋 이미지 + 원본 라벨을 참값(GT)으로 채택
02. 에러 바운딩박스 생성      → Python 스크립트로 조건별 라벨 자동 변형
03. 모델 학습과 평가 자동화   → 조건별 라벨로 YOLOv8n 파인튜닝 → 공통 평가셋으로 성능 측정
04. 오류 판단                 → 조건별 성능 패턴 DB 구축 → 블라인드 데이터 성능과 비교해 오류 유형 역추정
```

## 4. 실험 조건 매트릭스 (확정, 13개 조건)

| 그룹 | 조건 | 강도 | 실행 횟수 |
|---|---|---|---|
| 기준선 | Clean (원본 라벨) | 0% | 1 |
| 크기 오류 — 가로 | 가로 길이 변형 | -30% / -15% / +15% / +30% | 4 |
| 크기 오류 — 세로 | 세로 길이 변형 | -30% / -15% / +15% / +30% | 4 |
| 회전각 오류 | 중심점 기준 회전 | -15° / -7.5° / +7.5° / +15° | 4 |
| **합계** | | | **13회 학습·평가** |

- 오류 적용 비율: 전체 라벨 중 30%에만 적용 (나머지 70%는 정상 라벨 유지)
- 설계 원칙: 좌우 대칭(양/음 방향) 오류를 모두 검증하고, 강도도 2단계(약/강)로
  세분화해 오류 강도에 따른 성능 저하 곡선을 처음부터 매끄럽게 확보
- 중심점 이동(위치 오류)은 특허 청구항에 없는 보조 유형으로, 1차 실험에서는 제외하고
  시간 여유 시 추가 검증

### 실행 순서 — 중요도순으로 배치 (시간 리스크 관리)

13개 조건을 하나의 자동화 배치 스크립트로 순차 실행하되, 아래 순서를 지켜서
**중간에 시간이 부족해 멈추더라도 핵심 실험은 이미 끝나있도록** 한다.

```
1순위 (핵심 7개, 반드시 완료): clean, width±30, height±30, rot±15
2순위 (세분화 6개, 시간 허용 시): width±15, height±15, rot±7.5
```

1순위만으로도 "오류 유형별 성능 저하 패턴이 구분되는가"라는 핵심 가설을 검증하는
최소 완결 실험이 된다. 2순위까지 끝나면 강도별 성능 저하 곡선까지 확보해 더
설득력 있는 결과를 얻는다.

## 5. 모듈 구성

### ① 데이터 입력·전처리 모듈

- 이미지·라벨 파일 불러오기
- Car 클래스 우선 추출 (DontCare 영역 별도 처리)
- train·validation·test 고정 분할 (모든 오류 조건에서 동일하게 재사용)
- KITTI 라벨 → YOLO 포맷 변환
- 원본 라벨을 임시 참값(GT)으로 활용

**라이브러리**: pandas, numpy(라벨 처리) / OpenCV, Pillow(이미지 처리) / pathlib, PyYAML(파일·설정 관리)

> **핵심 원칙**: 오류 조건이 달라져도 이미지·분할·학습 하이퍼파라미터는 전 조건에서 동일하게 고정한다.
> 그래야 성능 차이가 순수하게 "라벨 오류" 때문이라고 말할 수 있다 (confounding 변수 통제).

### ② 에러 라벨 생성기

참값 라벨(cx, cy, w, h)에 조건별 변형을 적용해 조건별 라벨 폴더를 생성한다.

- 크기 변형: `w, h *= (1 + magnitude)` — 중심 고정
- 회전 변형: 박스 네 꼭짓점을 중심 기준 `angle`만큼 회전 → 회전된 꼭짓점을 다시
  감싸는 축정렬(axis-aligned) 사각형으로 재계산 (KITTI/YOLO는 회전 박스를 지원하지
  않으므로 필수)
- 적용 비율: 전체 라벨 중 30%만 무작위로 선택해 변형, 나머지는 원본 유지

### ③ 학습·평가 파이프라인

- 모델: Ultralytics YOLOv8n (pretrained, 파인튜닝)
- 조건별로 동일 하이퍼파라미터(에폭 수, 배치 크기, 시드)로 학습
- 공통 평가셋(원본 라벨 고정)으로 mAP@0.5, mAP@0.5:0.95, Precision, Recall 측정

### ④ 성능 패턴 DB

- 조건별 성능 지표를 CSV(`metrics.csv`)로 축적
- matplotlib/seaborn으로 오류 강도별 성능 저하 곡선 시각화

### ⑤ 진단 모듈

- 블라인드 데이터셋(오류 유형을 알려주지 않은 데이터)의 성능을 패턴 DB와 비교
- 가장 유사한 조건을 찾아 오류 유형을 역추정

## 6. 성능 지표

- mAP@0.5, mAP@0.5:0.95
- Precision, Recall (오류 유형별로 어떤 지표가 더 민감하게 반응하는지 확인)
- 오류 비율 증가에 따른 성능 감소 기울기

## 7. 성공 기준 (가안, 교수님 검토 필요)

- 각 오류 유형이 정상 데이터(0%) 대비 구분되는 성능 패턴을 보임
- 오류 강도 증가에 따라 성능이 단조적으로 감소
- 블라인드 데이터셋에서 오류 유형을 패턴 매칭으로 일정 수준 이상 분류

## 8. 기술 스택

| 분류 | 도구 | 용도 |
|---|---|---|
| 언어/런타임 | Python 3.10+ | 전체 파이프라인 구현 |
| 라벨 변형 | NumPy | 바운딩박스 좌표 변환(크기·회전 계산) |
| 데이터 포맷 처리 | PyYAML | YOLO `data.yaml` 설정 파일 관리 |
| 이미지 검증(선택) | OpenCV (cv2) | 변형된 라벨이 이미지에 잘 매핑되는지 시각적 확인 |
| 객체탐지 모델 | Ultralytics YOLOv8 (yolov8n.pt, pretrained) | 조건별 파인튜닝 및 평가 (PyTorch 백엔드) |
| 데이터 확보 | KITTI Devkit / Roboflow API | KITTI 원본 다운로드 또는 Roboflow의 YOLO 포맷 변환본 확보 |
| 학습 환경 | 로컬 (MacBook Pro M1, 16GB, `device='mps'`) | 조건별 파인튜닝 실행 |
| 학습 환경 (백업) | Google Colab (무료 T4 GPU) / AWS·GCP 크레딧 | 로컬 속도 이슈 시 대체 |
| 결과 저장 | Pandas + CSV | 조건별 mAP/Precision/Recall을 표 형태로 축적 |
| 시각화 | Matplotlib / Seaborn | 오류 강도별 성능 저하 곡선 그래프 생성 |
| 버전 관리 | Git / GitHub (private repo) | 라벨 변형 스크립트·실험 코드 버전 관리 |
| 환경 관리 | venv + requirements.txt | 팀원 간 동일한 실행 환경 보장 |

**선정 기준**: 전 구간에서 유료 AI API(LLM 등) 없이, 로컬 GPU(M1 MPS)와 무료/기확보
크레딧만으로 실험이 완결되도록 구성.

## 9. 남은 검증 필요 사항 (교수님 조언 요청)

1. 오류 유형별 성능 저하 패턴 비교로 실제 라벨 오류를 추정하는 접근의 기술적 타당성
2. 크기·회전각 오류가 서로 구분 가능한 성능 패턴을 만드는지
3. mAP 외에 함께 봐야 할 지표
4. 회전각 구간(±7.5°/±15°) 설정의 적절성
5. 2차 예선용 최소 실험 범위와 성공 기준
