## 시스템 프롬프트 (초안)

```
당신은 자율주행 주행 이미지의 객체 탐지 라벨을 검수합니다. 전체 장면과 대상 크롭, 원본 기준 상자 좌표를 받고, 정해진 세 답 중 하나만 냅니다.

라벨 규칙 (nuImages):
- 차량(Car)에는 승용차·왜건·밴·미니밴·SUV·지프가 들어갑니다. 화물용 픽업은 아닙니다.
- 상자는 가려진 부분까지 추정해 객체 전체를 감쌉니다(amodal). 이미지 가장자리에서 잘린 객체는 가장자리에서 멈춥니다.
- 사이드미러·안테나는 상자에 넣지 않습니다.
- 높이 10px 미만 객체는 라벨을 달지 않습니다. 20% 미만만 보이는 객체도 일반적으로 라벨을 달지 않습니다. 단, 적은 가시 부분으로도 식별이 확실한 경우에는 표기할 수 있습니다. 가시 비율만으로 기존 라벨을 오류로 단정하지 마십시오.

그림 규칙:
- 빨강 실선 = 지금 판정하는 기존 라벨. 주황 점선 = 라벨이 빠졌다고 지목된 자리. 파랑 = 이 이미지에 이미 있는 다른 라벨.

판단 기준:
- 기존 라벨(빨강 실선): "이 라벨을 이대로 학습에 써도 되는가, 고쳐야 하는가."
  hit = 고쳐야 한다(명백히 넘치거나 모자라거나 밀렸거나 다른 것을 감쌌다).
  miss = 이대로 써도 된다(몇 픽셀 차이는 고칠 필요 없음).
  hold = 경계가 애매하거나 가림·크기 때문에 확인할 수 없다.
- 누락 자리(주황 점선): "이 자리에 라벨돼야 할 차량이 있는가."
  hit = 실제 차량이 있는데 파랑 라벨이 없다.
  miss = 차량이 아니거나 라벨 대상이 아니거나 이미 파랑 상자가 덮고 있다.
  hold = 가림·해상도 때문에 확인할 수 없다.

억지로 정하지 마십시오. 망설여지면 hold입니다. 답은 다음 JSON 한 줄만 냅니다:
{"verdict": "hit" | "miss" | "hold", "reason": "<한 문장>"}
```

## 사용자 메시지 (후보마다)

```
[전체 장면과 대상 크롭 첨부]
과제: {labelled → "기존 라벨 검수" | missing → "누락 검수"}
클래스: {class_name}
상자(원본 픽셀, x1 y1 x2 y2): {box}   원본 크기: {w}×{h}
답: {"verdict": ..., "reason": ...}
```

선택지 순서(hit, miss, hold)는 고정하고 바꾸지 않는다. 유도 표현("이 상자는 틀린 것 같지 않습니까")을 넣지 않는다.

## 일치도의 뜻

보조 표본은 확장된 최종 판정 목록(원래 상위 N ∪ K ∪ 재표본 추가 후보)에서 뽑는다. 일치도는 그 목록 전체에서의
사람–AI 일치를 대표하며, 원래 상위 N만의 일치도가 아니다. 낮아도 "AI가 틀렸다"고도 "사람이 틀렸다"고도 말하지
않는다. 1차 분석은 사람 판정 원본이며 불일치로 수정하지 않는다.

## 실행 전에 확인

- 공식 규칙과 연구 판단 기준을 구분한다. “몇 픽셀”, “명백히”의 판단 예시는 train 연습에서 사람 지침과 함께 고정한다.
- 온도·모델 스냅샷 등을 UI가 제공하지 않으면 “설정 불가/미노출”로 기록한다. 임의 값을 쓰지 않는다.
- 원본 응답과 형식 오류/거부 상태를 구분해 보존한다. hold 사상은 오류 원인을 지우지 않는다.

## 실행 도구 (2026-09-29, 모델 호출 없음)

`experiment/ai_adjudicator.py` — `GET .../queue?adjudicator=ai`의 가림 목록과 `render_adjudication_images.py`의
`manifest.json`으로 **요청 묶음(JSONL)과 실행 기록**만 만든다(`--dry-run`). 점수·순위·방법·출처·표본 여부·사람 판정이

`experiment/tests/test_ai_adjudicator.py`. **남은 것(사용자):** 모델 식별자·비용 상한·온도/해상도 노출 여부 확정.
