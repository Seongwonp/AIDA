### 2026-07-06 — 2차 예선 참가 인원 확정

- **결정**: 박성원, 김해연 2인만 2차 예선(대전 캠프) 참가. 서정호·정경준은 디스코드로 원격 참여
- **이유**: 대회 규정상 팀원 5인 미만은 참가 인원 최대 2인으로 제한됨

### 2026-07-07 — 발표자료 디자인: 흑백 + 형광 하이라이트 사용 최소화

- **결정**: 발표자료(PPT) 전체를 흑/백 위주로 하고, 형광 라임(#CCFF00)은 표지·핵심 문구·
  핵심 통계 등 딱 5장에서만 하이라이터 마커처럼 사용. 카드/표/버튼 등 반복 요소에는
  형광 사용 금지
- **이유**: 초기 디자인이 "AI가 만든 느낌", "촌스럽다"는 피드백을 받음. 색상 남용,
  반복되는 박스/카드 그리드, 정형화된 레이아웃이 원인으로 지목됨. 박스형 카드 대신
  텍스트 위계(번호+제목+설명)와 얇은 구분선 위주의 에디토리얼 스타일로 전환

### 2026-07-07 — 발표자료 40장 구성 확정

- **결정**: 문제정의 → 솔루션/기술 → 차별성 → 시장분석 → 비즈니스모델 → 실행계획 → 팀,
  7개 섹션 40장으로 구성
- **이유**: 2차 예선 발표평가 배점(문제인식 20, MVP 구현가능성 25, 성장전략 25, 팀 15,
  발표역량 15) 전 항목을 커버하도록 설계

### 2026-07-07 — 특허 청구항과 오류 유형 정합성 확인

- **결정**: 특허(10-2664201) 청구항이 명시하는 오프셋 정보는 가로 길이·세로 길이·
  회전각 3가지뿐. "중심점 이동"은 청구항에 없음을 확인. 가로/세로/회전각을 **주 오류
  유형**, 중심점 이동은 **보조 유형**으로 구분하기로 함
- **이유**: 심사 기준에 "국방기술 활용 구체성"이 배점으로 들어가 있어, 특허 청구항과
  정확히 일치하는 오류 유형을 주력으로 내세우는 것이 방어하기 쉬운 포지션

### 2026-07-07 — 실험 조건 매트릭스: 7개로 확정 (이후 13개로 재확정, 아래 항목 참고)

- **결정**: 기준선(0%) + 가로(±30%) + 세로(±30%) + 회전각(±15°) = 7개 조건. 세분화
  (±15%, ±7.5° 등 5단계)는 1차 실험에서 신호가 확인된 이후 후속 로드맵으로 미룸
- **이유**: 5단계×3축 = 13회 학습·평가는 남은 시간(2차 예선 전 하루) 내 완료 불가능.
  coarse-first-then-refine 전략으로 시간 대비 검증 효율 확보
- **[변경됨]** 팀 내부적으로 이미 13개 조건으로 공유·인지된 상태였음이 확인되어,
  아래 2026-07-07(2) 항목에서 13개로 재확정함

### 2026-07-07 (2) — 실험 조건 매트릭스: 13개로 재확정

- **결정**: 기준선(0%) + 가로(±30%/±15%) + 세로(±30%/±15%) + 회전각(±15°/±7.5°) =
  13개 조건. 위 7개안을 다시 13개로 되돌림
- **이유**: 팀 내부에서 이미 13개 조건으로 공유된 상태였고, 13개 쪽이 성능 저하
  곡선을 처음부터 더 매끄럽게 확보할 수 있어 기술적으로 더 탄탄함
- **리스크 관리**: M1 Mac + YOLOv8n + 300~500장 기준 조건당 10~20분, 13개 총
  2~4시간 예상. 시간 리스크를 줄이기 위해 13개를 하나의 자동화 배치 스크립트로
  순차 실행하되, **핵심 7개(clean, width±30, height±30, rot±15)를 먼저 실행**하도록
  순서를 배치. 중간에 시간이 부족해 멈추더라도 핵심 실험은 이미 완료된 상태를 보장

### 2026-07-07 — MVP 데이터: 신규 이미지 생성 없이 KITTI 재활용

- **결정**: 가상 이미지를 3D 렌더링/합성으로 새로 만들지 않고, KITTI 공개 데이터셋의
  기존 이미지 + 원본 라벨을 "참값(GT)"으로 재활용. 자동화 대상은 "에러 라벨 생성"
  단계만
- **이유**: 특허 명세서상 "가상 이미지"의 핵심은 "참값을 정확히 아는 이미지"라는
  의미이지 "렌더링된 이미지"라는 뜻이 아님. 실제 이미지 생성 기술은 사업계획서상
  후속 로드맵 항목

### 2026-07-07 — 대상 클래스: Car 단일 클래스로 한정

- **결정**: KITTI의 여러 클래스(Car, Pedestrian, Cyclist 등) 중 Car만 사용
- **이유**: 클래스별 박스 종횡비 차이가 회전/크기 오류의 영향과 뒤섞이는 것을 방지.
  "성능 차이가 순수하게 주입한 오류 때문"이라는 인과관계를 더 명확히 주장하기 위함

### 2026-07-07 — 개발 환경: 유료 AI API 불필요 확인

- **결정**: 오류 라벨 생성(좌표 연산)과 YOLOv8 파인튜닝 모두 유료 LLM/AI API 없이
  로컬(M1 Mac, MPS) 또는 무료 Colab/기확보 클라우드 크레딧으로 완결
- **이유**: 팀이 "AI API 비용" 관련 우려를 표함. 실제로는 이 실험 자체가 좌표 계산과
  로컬 모델 학습이라 별도 유료 API 호출이 없음을 확인

### 2026-07-07 — MVP 데모: 웹 대시보드(FastAPI + React/TypeScript)로 결정

- **결정**: Streamlit/노트북 대신 FastAPI 백엔드 + React/TypeScript 프론트엔드로
  MVP 대시보드 구현
- **이유**: 사업계획서상 이미 "웹 기반 SaaS 플랫폼"으로 포지셔닝돼 있고, 정경준님
  역할(프론트엔드)과도 일치. 2차 예선 배점 중 "MVP 구현 가능성"(25점, 최대 배점)에서
  클릭 가능한 실제 화면이 스크립트/그래프보다 설득력이 높음. 다만 시간 제약상 스코프는
  결과 조회 대시보드 1페이지로 최소화

### 2026-07-08 — 핵심 7개 조건 학습: clean 이후 6개 조건만 50→25epoch로 단축

- **결정**: `run_all.py --priority 1` 실행 중 `clean`(50epoch) 완료 후, 나머지
  6개 조건(width±30, height±30, rot±15)은 25epoch로 줄여서 학습. 원래 계획은
  13개 조건 전체 동일 50epoch였음
- **이유**: 실제 실행해보니 M1 MPS 기준 조건당 학습이 예상(10~20분)보다 훨씬 느려
  `clean` 1개(50epoch)에만 약 1시간이 걸림 — 이 속도면 핵심 7개만 해도 7시간
  가까이 걸려 2차 예선(2026-07-09~10) 전 완료가 불확실해짐. 절대 성능 저하율보다
  "오류 유형별로 구분되는 패턴이 실제로 나타나는가"라는 핵심 가설 검증이 급선무라
  판단해 남은 조건의 epoch을 줄여 속도를 확보
- **트레이드오프**: 6개 오류 조건끼리는 모두 25epoch로 공정 비교 가능하지만,
  50epoch로 더 수렴한 clean과 비교한 절대 저하율(%)은 과대추정됐을 수 있음. 상세
  분석과 저비용 보완 방법(clean 25epoch 재실행)은
  [12-experiment-results.md](./12-experiment-results.md) "한계" 절 참고

### 2026-07-08 (2) — 학습 디바이스를 mps 하드코딩에서 auto 자동감지로 변경

- **결정**: `experiment/config.py`의 `AIDA_DEVICE` 기본값을 `mps`에서 `auto`로
  바꾸고, `resolve_device()`가 `cuda > mps > cpu` 순으로 실제 사용 가능한 디바이스를
  자동 감지하도록 재작성
- **이유**: 팀원이 CUDA GPU(RTX 3050)가 있는 데스크탑에도 이 저장소를 clone해서
  같이 실험을 돌리기로 함. 기존엔 `mps`가 기본값이라 CUDA 머신에서는 매번 `.env`를
  손으로 고쳐야 했음. `auto`로 바꾸면 M1 Mac이든 CUDA 데스크탑이든 같은 코드·같은
  `.env.example`로 각자 최적 디바이스를 자동으로 잡는다
- **후속 계획**: CUDA가 M1 MPS보다 훨씬 빠를 것으로 예상돼, 데스크탑에서는 13개
  조건 전체를 동일 50epoch로 재실행해 앞선 결정(2026-07-08)에서 생긴 epoch 불일치
  한계를 없앨 계획 — [09-getting-started.md](./09-getting-started.md) "아직 안 된 것"
