# timing4 — 실제 진단 후보로 재는 판정 시간 (사전 등록)

> **이 문서는 판정을 시작하기 전에 고정한다.** 결과를 보고 고치지 않는다.
>
> 작성 2026-09-10.

## 왜 다시 재는가

timing1~3의 후보는 **주입한 오류**였다. 종류가 셋뿐(40% 늘리기·35% 줄이기·
30% 옮기기)이고 전부 눈에 띄게 커서, 실제 후보보다 빨리 판단된다.

거기서 나온 `s_plan = 3.05초`는 **하한**이다. `N = (T/D)/s_plan`이라 분모가
작으면 N이 과대해지고, 보수적으로 잡으려던 시간 상한이 오히려 깨진다.

**이 파일럿이 유일한 해결책이라는 뜻은 아니다.** 안전계수를 명시해 쓰거나 N을
뒤로 미루는 길도 있었다. 실제 후보로 재는 쪽을 고른 것은 **분모를 실제와 같은
난이도에서 잰다**는 한 가지 이유 때문이고, 이것도 아래 "대표성 한계"의 제약을
그대로 받는다.

## 후보를 어디서 가져오는가

기존 산출물에는 실제 진단 큐가 없다. `box_accuracy_verdicts*.json`은 후보별
행을 담지만 **이미지 이름도 박스 좌표도 없어** 화면에 그릴 수 없고, `review_queue`를
가진 파일은 **사용자 데이터셋 5개뿐이라 쓰지 않는다.**

그래서 개발 데이터에 자를 한 번 돌린다.

| | |
|---|---|
| 이미지 | `data/processed/images/val`의 KITTI 프레임 |
| 라벨 | `data/processed/labels_gt_nested/val` (원본 그대로, **주입 없음**) |
| 자 | `runs/clean/weights/best.pt` (SHA-256 `4e998fa7a6dfddae…`) |
| 학습 | **하지 않는다.** 추론만 |
| 최종 평가 데이터·사용자 데이터셋 | **쓰지 않는다** |

**빼는 것 셋.**

1. timing1~3이 쓴 이미지 (판정자가 이미 봤다)
2. **자의 학습 라벨(`labels_gt/train`)에 있는 stem**
3. **`images/train`에도 사본이 있는 것**

2·3은 **자가 본 적 있는 프레임**을 걸러내려는 것이다. 학습에 쓴 프레임은 모델이
유난히 잘 맞혀 후보가 적게·다르게 나오고, 그걸로 잰 시간은 실제와 다르다.
논리적 분할과 파일이 놓인 자리가 달라 **둘 다** 봐야 한다(docs/25 2단계에서
겪은 함정과 같은 것).

> **정정 (판정 시작 전).** 처음에는 `labels_gt/val`을 쓰려 했는데 라벨이 120장뿐이고
> timing1~3이 이미 72장을 써서 48장밖에 안 남았다. 실제 후보 40건을 못 채운다.
> 그래서 같은 KITTI 정답의 더 큰 세트(`labels_gt_nested/val`, 800장)로 바꿨고,
> 위 세 조건을 걸어 **자에게 안 보인 679장**만 남겼다. **결과를 보기 전에 바꾼
> 것이고, 이유는 표본 부족이지 결과가 아니다.**

실행 명세(사용 이미지 목록, 가중치 SHA-256, 코드 커밋, 설정, 생성 시각)를
`pilot_manifest.json`에 남긴다.

**라벨이 원본이므로 실제 후보 대부분은 자의 오탐일 것이다.** 그래도 난이도는
실제와 같다 — 미묘한 기하 차이, 놓친 탐지, 겹침. 그게 이 파일럿이 재려는 것이다.

## 무엇을 고정하는가

| 항목 | 값 |
|---|---|
| 실제 후보 | **40건** |
| anchor | **8건** (정상 4 · 명백한 오류 4) |
| 전체 | **48건** |
| 표집 시드 | **`4107`** |
| 세션 | **3세션 × 16건** |
| 총 활동 시간 상한 | **25분** (넘기면 그 세션에서 멈춘다) |
| 판정 방식 | `unaided_human` |
| 후보 출처 | `actual_diagnosis` |

**후보 유형을 인위적으로 균등하게 만들지 않는다.** 실제 큐의 구성 비율을 그대로
쓴다 — 균등하게 만들면 그건 이미 실제 큐가 아니다. 표집 전 전체 후보 수와
구성, 표집 후 구성을 명세에 적는다.

**AIDA 점수·순위·severity·세부 의심 유형은 화면에서 계속 가린다.** 보이는 것은
이미지, 후보 박스, 주변 기존 라벨, 클래스뿐이다.

### 실제로 만들어진 것 (2026-09-10)

이미지 120장에 자를 돌려 **실제 후보 138건**이
나왔다(기존 라벨 120 / 누락 18).

| | 표집 전 | 표집 후 |
|---|---|---|
| 전체 | 138 | 40 |
| 기존 라벨 / 누락 | 120 / 18 | 37 / 3 |
| 유형 | `{'duplicate': 4, 'height': 34, 'missing': 18, 'scale': 18, 'translation_x': 10, 'translation_y': 7, 'width': 47}` | `{'height': 9, 'missing': 3, 'scale': 9, 'translation_x': 2, 'translation_y': 3, 'width': 14}` |

**유형을 고르게 만들지 않았다.** 시드 4107로 그냥 무작위
표집했고, 구성은 실제 큐를 따라간다.

명세는 `uploads/ffffffffff06/pilot_manifest.json`에 있다 — 사용 이미지 목록,
가중치 SHA-256, 코드 커밋, 설정, 생성 시각.

## anchor — 품질 가드레일이지 정확도 증거가 아니다

실제 후보에는 **정답이 없다.** 그래서 그것만으로는 "빨라진 것이 숙련인지
무성의인지"를 가릴 수 없다.

정답이 알려진 후보 8건을 섞는다.

| anchor | 무엇 | 기대 |
|---|---|---|
| 정상 4건 | 원본 라벨 그대로 | `오류 아니었다` |
| 오류 4건 | 크게 어긋나게 주입 | `오류였다` |

**판정 중에는 실제 후보와 구분할 수 없다.** 화면에 표시가 없고, 정답표는
완료 전 열지 않는다.

> **anchor 정확도는 AIDA의 효능이 아니다.** 주입한 오류를 사람이 알아보는지를
> 볼 뿐이고, 실제 후보의 판정 정확도와도 무관하다. **과속·무성의 판정을 잡는
> 가드레일**로만 읽는다.

### 허용 기준은 아직 없다

"정상 anchor 오탐이 몇 건까지 괜찮은가"에 **근거가 없다.** 결과를 보고 정하면
그건 기준이 아니라 사후 설명이다.

그래서 **숫자를 만들지 않는다.** 보고서는 anchor 결과를 그대로 적고
`quality_threshold_not_preregistered`로 남긴다. **시간 통계와 N 확정을
분리한다** — 시간은 나오되 N은 사람이 anchor 결과를 보고 판단한다.

## 판정 규약

**주소는 하나다**(`?evaluate=ffffffffff06:timing4`). timing3처럼 주소를 셋으로
나누면 후보 집합도 셋으로 갈라져 **실제 큐의 구성 비율이 블록마다 흔들린다.**
여기서는 구성 보존이 더 중요하므로 한 묶음으로 두고, **세션 분리는 사람이
16건마다 탭을 닫는 것으로** 한다.

다시 열면 아직 판정하지 않은 후보에서 이어진다.

1. 주소를 열고 **16건**을 판정한 뒤 **탭을 닫는다.** 세 번 반복한다.
2. **도움 없이** 판정한다. 화면을 캡처해 다른 도구에 묻지 않는다.
3. **애매하면 `모르겠다`.** 억지로 정하지 않는다.
4. 다른 앱에서 고민한 시간은 활동 시간에서 빠진다 — **화면을 보면서** 판단한다.
5. 25분을 넘기면 그 세션에서 멈추고 남은 것은 미판정으로 둔다.

판정 기준(무엇이 `오류였다`인지)은 [manual-timing-pilot.md](manual-timing-pilot.md)와
같다.

## 반드시 보고할 것

- 세션별 평균과 **첫 세션 대 마지막 세션의 속도 차이**
- anchor 결과(정상/오류 각각)
- **실제 후보에는 정답이 없으므로 accuracy를 계산하지 않는다**
- 표집 전후 구성 비율

## N을 내는 조건

아래가 **전부** 참일 때만 N 후보값을 낸다.

- `timing_usable = true`
- `judging_mode = unaided_human`
- `candidate_source = actual_diagnosis`
- 중복 이벤트 0, 빠진 순번 0
- 사전 등록한 세션 수(3) 충족
- **속도 증가와 정상 anchor 오탐을 사람이 검토 완료**

마지막 항목은 자동으로 판정하지 않는다. 기준이 사전 등록돼 있지 않기 때문이다.

## 대표성 한계 — 이 파일럿이 말하지 않는 것

- **판정자가 한 명이고 이미 세 차례 연습했다.** 숙련 운영자의 속도에 가깝고
  신규 사용자의 속도가 아니다.
- **개발 데이터의 진단 후보가 고객 데이터의 후보를 대표한다는 보장이 없다.**
  KITTI 주행 장면, 단일 클래스(Car), 우리가 만든 자의 출력이다.
- **실제 후보의 판정 정확도는 모른다.** 정답이 없고, 외부 판정자나 합의 정답도
  없다.
- anchor는 주입한 오류라 timing1~3과 같은 한계를 갖는다.
- 여기서 나온 `s_plan`도 **확률 보장이 아니라 보수적 참고값**이다.
