# 독립 평가 데이터 — 후보와 중복 확인

> docs/24 C1. **아직 고르지 않았다.** 이 문서는 "무엇을 만족해야 하는가"와
> "후보가 무엇인가", 그리고 **겹침을 어떻게 재는가**를 정한다.
>
> 표기 규칙은 [24-development-plan.md](./24-development-plan.md)를 따른다.
> 라이선스·등록 조건은 **바뀌는 정보**라 여기서 단정하지 않는다 —
> 쓰기로 정한 뒤 직접 확인한다.

## 왜 필요한가

지금까지의 모든 수치는 **KITTI와 COCO에 우리가 오류를 주입한 것**에서 나왔다
([current-evidence.md](./current-evidence.md) 맨 앞). 그리고 **자가 그 두
데이터로 학습됐다.**

- 자연 발생 오류로 검증한 적이 없다.
- 자가 이미 본 이미지를 진단하면 성능이 실제보다 좋게 나온다.

## 만족해야 하는 것

| | 조건 | 이유 |
|---|---|---|
| 1 | **자의 학습 데이터와 겹치지 않는다** | 겹치면 이미 본 것을 진단하는 셈이다 |
| 2 | 2D 박스 라벨이 있다 | 진단 대상이 그것이다 |
| 3 | 클래스 **의미**가 대응된다 | COCO `bicycle`(자전거)과 KITTI `Cyclist`(탄 사람)는 다르다(docs/21 AI) |
| 4 | 라이선스가 이 용도를 허용한다 | 연구·개인 평가 범위 |
| 5 | 받을 수 있다 | 계정·승인 절차의 유무 |

**3번을 가볍게 보면 안 된다.** COCO를 고를 때도 `Car` 하나만 쓴 이유가
그것이었다 — 애매한 매핑을 넣으면 "도메인이 달라서 무너진 것"과 "라벨 정의가
달라서 무너진 것"이 섞인다.

## 먼저 빼야 하는 것 — 겹침이 확실한 후보

| 데이터 | 왜 빼는가 |
|---|---|
| **LVIS** | **COCO 이미지 위에 만든 라벨**이다. 독립이 아니다 |
| **COCO-Stuff, COCO 계열 재라벨링** | 같은 이유 |
| **KITTI-360, KITTI 다른 과제** | 같은 촬영에서 나온 프레임이라 장면이 겹친다 |

**이건 "확인해 보면 겹칠 수도 있다"가 아니라 구조적으로 겹치는 것들이다.**

## 후보 — 전부 `확인 필요` 상태다

라이선스·등록 조건은 **바뀌므로 여기 적은 것을 근거로 쓰지 않는다.** 고른 뒤에
직접 확인하고 그때 이 표를 결과로 바꾼다.

| 후보 | 성격 | 겹침 위험 | 확인해야 할 것 |
|---|---|---|---|
| **BDD100K** | 주행 영상, 대규모 | 낮음(다른 촬영) | 계정 필요 여부, 라이선스 범위 |
| **Cityscapes** | 주행, 도시 | 낮음 | 계정, 학술 한정 여부 |
| **nuScenes** | 주행, 다중 센서 | 낮음 | 계정, 비상업 조건 |
| **Open Images** | 일반 물체, 대규모 | **중간** — COCO와 같이 Flickr에서 왔다 | 라이선스, **COCO와의 근접 중복** |
| **Pascal VOC** | 일반 물체, 소규모 | **중간** — 같은 이유 | 위와 같음 |
| **Objects365** | 일반 물체, 대규모 | 낮음~중간 | 계정, 라이선스 |

저장소에 이미 적혀 있는 관찰 하나: `download_coco.py`에 **"BDD100K·Cityscapes·
nuScenes는 전부 계정이 필요하다"**고 남아 있다(2026-09 시점 관찰). COCO를 고른
이유가 그것이었다.

**Open Images와 Pascal VOC의 겹침 위험이 중간인 이유**는 COCO도 Flickr에서
모았기 때문이다. 같은 사진이 양쪽에 들어갔을 수 있다. 아래 도구로 재야 한다.

## 자연 발생 오류를 어디서 구하는가 — 아직 답이 없다

docs/24 C의 완료 판정이 이렇게 적혀 있다.

> 자연 오류를 확보하지 못하면 합성 평가로 진행하되 **자연 오류 검증으로
> 표현하지 않는다.**

공개 데이터의 라벨 오류를 **정답까지 갖춰 공개한 자료**를 아직 못 찾았다.
가능한 길 셋과 각각의 문제:

| 길 | 문제 |
|---|---|
| 공개 데이터의 원본 라벨을 그대로 쓰고 우리가 다시 라벨링 | 우리가 정답을 만드는 것이라 편향된다 |
| 라벨 품질 연구가 공개한 오류 목록을 쓴다 | 대상이 대개 COCO다(겹침) |
| 크라우드 라벨링 결과가 공개된 데이터 | 찾아야 한다 |

**지금 정하지 않는다.** C 단계에서 평가 규약을 쓸 때 "합성만 한다"를 명시할지
결정한다.

## 겹침을 어떻게 재는가 — 실제로 돌아가는 도구

`experiment/check_dataset_overlap.py`

```bash
python check_dataset_overlap.py --candidate <새 데이터 이미지 폴더>
```

dHash(차이 해시)로 잰다. 이미지를 9×8 회색조로 줄이고 가로 이웃 픽셀의 대소를
64비트로 적어, 해밍 거리로 견준다.

**KITTI와 COCO가 한 폴더에 섞여 있어**(`data/processed/images`, 5,790장) 폴더
전체를 상대로 잰다. 갈라 봐야 얻을 것이 없고 빠뜨릴 위험만 있다.

### 무엇을 잡고 무엇을 못 잡는지 실제로 쟀다 (2026-09-08)

학습에 쓴 이미지 8장을 변형해 후보로 넣어 봤다.

| 변형 | 결과 |
|---|---|
| 크기 60%로 축소 | **8/8 잡음** |
| 화질 70으로 재인코딩 | **8/8 잡음** |
| 가장자리 잘라내기(66%만 남김) | **0/8 — 전혀 못 잡음** |
| 좌우 뒤집기 | **0/8 — 전혀 못 잡음** |

**"겹침 없음"은 겹침이 없다는 증명이 아니다.** 자르기와 뒤집기는 통째로
놓친다. 도구도 출력에 그렇게 말한다.

비슷한 장면(같은 도로를 몇 초 뒤에 찍은 프레임)도 가깝게 나오는데, 그것도
알아야 하는 정보다 — docs/24 C가 "연속 장면 등 가까운 표본"을 함께 확인하라고
적은 이유다. **문턱은 판정이 아니라 사람이 볼 목록을 만드는 값이다.**

## 아직 정하지 못한 것 — 사용자에게 물어야 한다

docs/24 C의 항목 중 혼자 정할 수 없는 것들이다.

- **데이터 권한·보관·삭제.** 어디에 얼마나 두고 언제 지우는가. 용량도 문제다 —
  BDD100K는 전체가 수십 GB다.
- **자연 오류를 구할 수 있는가.** 위 세 길 중 어느 것도 무료가 아니다.
- **비용 상한.** docs/24가 "비용 상한"을 고정 항목으로 적었다.

**이 셋이 정해지기 전에는 C2(평가 규약)를 쓸 수 없다** — 규약은 결과를 보기
전에 고정해야 하는데, 무엇으로 평가할지 모르면 고정할 것이 없다.
