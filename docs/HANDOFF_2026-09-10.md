## 2. 해석의 경계 — 여기서 벗어나면 안 된다

- **timing4는 처음으로 형식 요건을 충족했지만, 가장 긴 연속 판정이 16건·약
  1분이다. 1시간 지속 작업으로 외삽할 수 없다.**
- `s_plan = 3.58초`는 **짧은 블록에서의 관측값**이며 **현재 공식 N 계산에
  사용하지 않는다.**
- **`N = 1005`는 채택값이 아니다.** 근거가 부족한 단순 산술 예시일 뿐이다.
- 실제 후보가 주입 후보보다 **16% 느렸다는 결과만으로 난이도 차이와 숙련
  효과를 분리할 수 없다.**
- **같은 판정자가 반복했으므로 외부 사용자나 신규 사용자 속도로 일반화하지
  않는다.**
- **정상 라벨을 오류로 판정하는 경향 때문에 절대 precision·hit 수치는 부풀 수
  있다.**
- 같은 판정을 공유하므로 **방법 간 차이는 상대적으로 덜 영향을 받지만, 편향이
  완전히 상쇄된다고 단정하지 않는다.**
- **anchor는 주의력 가드레일이며, 실제 자연 오류의 정답 정확도를 증명하지
  않는다.**
- **품질 허용 기준은 사전 등록되지 않았으므로 사후에 통과/실패를 만들지
  않는다.**

## 3. 오늘 내린 결정

- **다음 작업은 지속 판정 파일럿(선택지 1)이다.**
- **오늘 밤에는 실행하지 않는다.**
- 선택지 2(16건 블록 외삽)와 선택지 3(임의 safety factor)은 **채택하지 않는다.**
- **지속 판정 결과를 보기 전에 성공 기준과 분석법을 별도 커밋으로 고정한다.**
- **`--reviewed`는 단순 확인 버튼이 아니다.** 문서화된 검토 항목을 충족한
  경우에만 쓴다.

## 4. 내일 시작할 작업 — 계획만, 데이터는 아직 만들지 않는다

### 자료

- 개발 전용 `actual_diagnosis` 후보 **100~150건**
- **최종 평가 데이터와 사용자 데이터셋 5개는 쓰지 않는다**
- timing1~4가 쓴 이미지·후보의 재사용 여부를 확인하고 **가능하면 중복 제외**
- 자가 본 적 있는 프레임 제외 규칙은 그대로 유지
  (`labels_gt/train` stem + `images/train` 사본)
- **고정 seed와 후보 목록 hash 기록**
- 실제 후보와 숨은 anchor의 **구성과 비율을 실행 전에 고정**

### 수행

- **한 번의 연속 판정**으로 수행한다
- idle · 탭 비활성 · wait 시간은 **기존 규칙대로 제외**
- **구간 단위를 실행 전에 고정한다** — 예: 1~25 / 26~50 / 51~75 / 76~100
- Codex·Gemini에 **개별 판정을 묻지 않는다**
- 새 anchor 정답표는 **완료 전 열람 금지**
- **피로하거나 평소 작업 속도가 아니면 중단하고 그 사실을 기록한다**

### 보고

- 구간별 **후보당 시간 · hold율 · anchor(정상 오탐 / 오류 탐지)**
- **첫 구간 대비 후반 구간의 속도와 품질 변화**
- 품질 기준이 근거 없이 정해질 수 없다면 **N은 계속 차단**
- 지속 판정 후에도 **바로 N을 확정하지 않고** 결과와 외삽 가능성을 먼저 검토

## 6. 완료와 미완료
