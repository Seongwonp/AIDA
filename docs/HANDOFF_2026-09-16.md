## 무엇이 바뀌었나

**진단** (`experiment/label_diagnosis.py`, `diagnose_labels.py`)

- 규칙에 걸린 후보 외에 **모든 기존 라벨**(`all_labels`, 라벨마다 `label_iou`)과 **누락 필터 전
  미매칭 예측**(`unmatched_predictions`, 확신도·삼켜짐)을 결과 파일에 적는다.
- 모집단을 안 모은 실행은 그 키 자체가 없다 — 옛 결과와 구분되고, 그런 진단으로는 후보 생성
  비교를 못 돌린다.

**평가** (`backend/app/routers/evaluation.py`)

| 무엇 | 규칙 |
|---|---|
| 후보 출처 | `aida_candidate` / `label`(규칙 밖) / `unmatched_prediction`(필터가 버린 것) |
| 병합 | 같은 대상은 **한 번만** 얼린다. 기존 라벨은 (이미지, 라벨 번호), 누락은 (이미지, 상자)로 잇는다 |
| 상자 충돌 | 상자가 같은 미매칭 예측이 둘이면 **얼리기를 거부한다**(조용히 덮어쓰지 않는다) |
| 방법 | 기존 라벨 층 `aida`·`iou_baseline`·`all_label_iou`, 누락 층 `aida`·`unmatched_confidence` |
| 예산 | 방법마다 **자기 모집단에서** 상위 N. 모집단이 작으면 남는 예산을 안 쓴다 |
| 비교 모드 | 기본 `within_aida_candidates`(prelim1과 같은 질문) / `candidate_generation_included`(Q-A·Q-C) |
| 무작위 표본 | 규칙 밖 라벨에서 K건, 씨앗 필수. 판정 대상에 더해질 뿐 **어느 방법의 상위 N도 바꾸지 않는다** |

**집계** (`experiment/evaluation/`)

- 짝지은 차이·부트스트랩은 **기본적으로 후보 집합이 같아야** 한다(정렬 효과). 후보 생성까지
  포함한 비교는 `require_same_candidates=False`로 **밝혀야** 돌고, 짝지음 단위는 그때
  **이미지 묶음**이다. 결과에 `same_candidate_set`이 남는다.

**옛 묶음은 아무것도 안 바뀐다.** prelim1의 후보 이름·지문(`e996e262…`)과 진단 파일 해시를
다시 확인했다.
