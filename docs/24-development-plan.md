# 24. AIDA 장기 개발·검증 계획

작성일: 2026-09-07  
상태: 사용자와 방향 합의, 문서화 완료. 구현과 신규 평가는 미착수.  
계획 수립 시 확인한 코드: `8c01da38b9f2c44f8e4f4885441f2e0b8d4a7011`

## 목표와 배경

**제한된 시간 안에 사람이 실제 객체 탐지 라벨 오류를 더 잘 찾도록 돕는 검수 도구를 만든다.**

사용자 설명에 따르면 AIDA는 국방기술창업경진대회에서 1차를 통과하고 2차에서 15팀 중 6위로 탈락한 뒤, 개인 연구·개발로 이어졌다. 순위는 사용자 제공 이력이며 공식 결과 자료로 독립 검증한 수치는 아니다. 대회 당시 기여와 이후 개인 기여는 별도로 정리한다.

지금까지의 가설 검증, 불공정한 조건의 수정, 시드 재검증, 외부 데이터에서의 한계 확인, 실패한 자기 정제 기록을 보존한다. 앞으로는 실험 조건의 증가 자체보다 **재현성 → 검수 기록의 정확성 → 독립 데이터 평가 → 사용자 평가 → 근거에 따른 개선**을 우선한다.

핵심 질문:

> 같은 검수 예산에서 AIDA가 무작위 검수나 단순한 추천 방식보다 더 많은 고유 오류를 발견하게 하는가?

현재 연구의 출발점은 [실험 기록](21-next-plan.md), [이전 계획](23-plan.md), [변경 이력](../CHANGELOG.md)이다. 이 문서는 미래 작업 계획이며 성능 개선을 이미 달성했다는 보고서가 아니다.

## 상태와 근거 표기 규칙

다음 상태를 구분한다: **코드로 구현됨 / 자동 테스트로 검증됨 / 제한된 실험에서 관찰됨 / 외부 데이터로 검증됨 / 실제 사용자·고객 데이터로 검증됨 / 계획 / 현재 미검증**.

- 성능 수치는 실제 결과 파일이나 테스트 로그를 확인하고 인용한다. 없으면 `근거 미확인`으로 표시한다.
- 개발자 자체 평가는 외부 사용자 평가와 구분한다. 외부 공개 데이터는 고객 데이터가 아니다.
- 계획상 기간·표본 목표·예산은 관측 결과와 구분한다.
- 개인정보, API 키, 환경변수의 비밀값, 로컬 사용자 경로를 문서·로그에 남기지 않는다.
- 과거 실험의 재현 정보를 복원할 수 없다면 추정해 채우지 않고 누락을 표시한다.

## 일정과 단계 의존성

아래 기간은 혼자 진행할 때의 **계획상 추정치**다. 전체 약 4~6개월을 예상하지만 데이터 확보·참여자 모집·작업 시간에 따라 달라진다. 날짜보다 완료 조건을 우선한다. 데이터 확보와 모집 준비는 앞 단계와 병행할 수 있다.

| 단계 | 예상 기간 | 산출물 | 완료 조건 |
|---|---|---|---|
| A. 연구 기준선 정리 | 1~2주 | 최신 근거 목록, 재현 정보 | 주장에서 결과·평가 코드까지 추적 가능 |
| B. 검수 기능 안정화 | 2~3주 | 후보 식별·저장·CSV 검증 | 판정 기록을 신뢰할 수 있음 |
| C. 독립 평가 설계 | 1~2주 | 사전 평가 계획, 분할, 판정 지침 | 결과 열람 전에 기준 고정 |
| D. 독립 데이터 평가 | 3~4주 | 비교 결과와 실패 분석 | 적용 범위와 개선 여부 판단 가능 |
| E. 사용자 예비 평가 | 3~5주 | 검수 효율·사용성 기록 | 알고리즘 문제와 사용성 문제 분리 |
| F. 선택적 개선 연구 | 4~6주 | 선택한 개선안과 재평가 | 단순 기준 대비 추가 가치 판단 |
| G. 배포·성과 정리 | 2~3주 | 실행 가능한 시연과 보고서 | 다른 사람이 실행·근거 확인 가능 |

B가 끝나기 전의 사용 기록은 정식 효과 평가에 사용하지 않는다. C에서 고정한 방법을 D에 사용한다. D·E의 결과를 보고 F의 연구 주제를 선택한다. 개선이 없으면 기능을 추가하지 않고 범위를 좁히거나 기존 방법을 유지한다.

## C. 독립 평가 설계

- [ ] `evaluation-protocol.md`를 작성하고 결과 확인 전에 고정한다.
- [ ] 개발·보정·최종 평가 데이터를 분리한다.
- [ ] 기준 모델 학습 데이터와 진단 평가 데이터의 관계를 명시한다.
- [ ] 중복 이미지와 연속 장면 등 가까운 표본의 분할 간 중복을 확인한다.
- [ ] 새로운 이미지의 통제된 합성 오류 평가와 자연 발생 오류 평가를 분리한다.
- [ ] 혼합 오류, 오류가 거의 없는 데이터, 모델과 분포가 다른 데이터를 검토한다.
- [ ] 데이터 권한·보관·삭제 방식과 평가에 사용할 범위를 정한다.

고정할 항목: 주지표·보조지표, 비교 방법, 포함/제외 기준, 표본 단위, 중복 처리, 판정 지침, 집계 방법, 불확실성 보고 방식, 성공/보류/중단 기준, 비용 상한.

표본 규모와 실용적인 최소 개선 폭은 지금 임의의 성과 목표로 정하지 않는다. 예비 평가에서 오류 빈도와 소요 시간을 파악한 뒤 최종 평가 전에 근거와 함께 고정한다. 예비 평가 데이터는 최종 평가에 재사용하지 않는다.

평가 결과를 보고 규칙을 수정했다면 그 데이터는 개발 데이터로 취급한다. 수정된 방법의 최종 평가는 별도로 보존한 데이터에서 진행한다.

**완료 판정:** 결과가 좋거나 나쁠 때의 후속 행동을 결과 열람 전에 설명할 수 있다. 자연 오류를 확보하지 못하면 합성 평가로 진행하되 자연 오류 검증으로 표현하지 않는다.

## D. 독립 데이터 평가

### 비교군

- 무작위 순서
- 단순 모델–라벨 불일치 점수
- 고정된 현재 AIDA
- 필요시 핵심 규칙을 제거한 AIDA: 어떤 규칙이 추가 가치를 만드는지 확인

동일 후보 안에서 순서만 섞는 비교는 **정렬 효과**, 전체 이미지에서 무작위로 검수하는 비교는 **작업 전체의 효과**다. 두 비교를 혼동하지 않는다.

### 평가 단위와 지표

이미지, 기존 라벨, 누락 객체, 진단 후보, 고유 오류를 구분한다. 같은 잘못된 박스를 여러 유형으로 지목해도 고유 오류를 중복 계산하지 않는다.

- 고정 검수량에서 발견한 고유 오류 수
- 유형별 정밀도와 추천 밖에서 놓친 오류
- 상위 비율 정밀도: 분모·반올림·최소 후보 수·빈 결과 처리를 명시
- 데이터셋별 결과와 전체 집계: 가중 방식 명시
- 오류가 적을 때 발생하는 불필요한 추천
- `order_risk`의 실제 실패 포착과 불필요한 경고

추천된 항목 밖에서도 무작위 표본 또는 정의된 정답셋을 평가한다. 전체 정답을 확보하지 못했다면 재현율을 확정적으로 주장하지 않는다. 학습 시드 변동과 평가 표본 변동은 별도로 보고하고, 같은 이미지에서 나온 후보들을 독립 표본으로 과대 계산하지 않는다.

`order_risk=false`는 안전 보장이 아니다. 평가 전 고정한 기준에 따라 위험 경고가 놓친 실패도 확인한다.

**완료 판정:** 평균 외에 조건별 이득·손해와 불확실성을 보고한다. 최종 평가에서 이기지 못하면 해당 결과를 그대로 남기고 F의 개선 질문으로 연결한다.

## E. 사용자 예비 평가

- [ ] 개발자 자체 예비 평가로 기록 장치와 판정 지침을 확인한다.
- [ ] 외부 참여자의 사용성 평가와 비교 효과 평가를 구분한다.
- [ ] 모집 대상·데이터 접근 범위·평가 안내를 준비한다. 외부 연락은 사용자 승인 후 진행한다.
- [ ] 서로 다른 데이터 묶음과 사용 순서를 배치해 기억·학습 효과를 줄인다.
- [ ] 가능한 경우 정답 판정자는 추천 점수와 순서를 보지 않도록 한다.
- [ ] 애매한 사례는 보류·재검토하고 사용자 판정을 무조건 정답으로 취급하지 않는다.

기록: 활동 시간과 대기 시간, 검수한 이미지·후보, 고유 오류, 보류·취소·수정 판정, 저장 실패, 추천 근거·경고의 이해 여부. 단순히 페이지가 열린 시간을 검수 시간으로 간주하지 않는다.

**주요 사용 가치 지표:** 동일한 실제 활동 시간에 발견한 고유 오류. 예비 평가에서 시간 측정이 불안정하면 원인을 고친 후 정식 평가한다.

**완료 판정:** 알고리즘이 나쁜지, 화면이 느린지, 판정 지침이 애매한지 분리할 수 있다. 참여자가 없으면 자체 평가까지 진행하고 외부 사용자 검증은 미완료로 남긴다.

## F. 결과에 따라 선택하는 개선 연구

모든 갈래를 동시에 진행하지 않는다.

| 확인된 병목 | 선택할 작업 |
|---|---|
| 오류 후보는 있으나 순서가 나쁨 | 순위 보정 |
| 모델이 객체를 발견하지 못함 | 모델 적합성·지원 범위 검토 |
| 사람 판정으로 데이터별 패턴이 드러남 | 소량 판정 기반 보정 |
| 위험 신호가 실패를 구분함 | 추천 보류·무작위 표본 검수 전환 평가 |
| 추천은 유효하나 작업이 느림 | 검수 동선·UI 개선 |
| 수정 결과를 활용하기 어려움 | 라벨링 도구 연계 |

우선 연구 후보는 **소량의 사람 판정으로 새로운 데이터의 순서를 보정하는 방법**이다. 보정에 쓴 판정과 평가 항목을 분리하고 현재 AIDA 및 단순한 유형별 보정과 비교한다. 효과는 현재 미검증이다.

검수 가치가 확인되면 사람이 수정한 라벨의 학습 효과를 검토한다. 동일한 수정 예산에서 AIDA 추천과 무작위 검수를 비교하고 독립된 깨끗한 평가셋에서 모델을 평가한다. 기존 이미지 폐기형 자기 정제와 다른 가설로 취급한다.

장시간 학습·유료 서비스·비용이 발생하는 실행은 방법, 예상 자원, 상한을 제시하고 사용자 확인 후 진행한다.

**완료 판정:** 추가 복잡성의 이득이 확인되지 않으면 채택하지 않는다. 실패한 개선도 결과와 범위를 기록한다.

## G. 배포와 성과 정리

- [ ] 개인 사용이면 로컬 실행의 재현성을 먼저 확보한다.
- [ ] 원격 사용이면 필요한 접근 통제·데이터 분리·삭제 정책을 준비한다.
- [ ] 동시 사용이 필요해지면 DB·작업 큐·충돌 처리를 검토한다.
- [ ] 공개 가능한 작은 예제, 실행 방법, 환경·가중치 정보를 제공한다.
- [ ] 독립 평가와 실패 사례, 적용 범위, 미검증 항목을 정리한다.
- [ ] 대회 MVP와 개인 고도화 결과를 기여 근거와 함께 구분한다.

인증·DB는 기능 목록을 채우려고 만들지 않는다. 외부 접근이나 동시 사용에 필요해지면 선행 조건으로 구현한다. 배포 실행은 구체적인 대상과 데이터 범위를 정한 뒤 진행한다.

**완료 판정:** 다른 사람이 실행하고 핵심 주장에 대한 근거를 확인할 수 있다. 상용 수준이나 보편적인 성능을 주장하지 않는다.

## 운영과 중단 기준

작업마다 `질문 → 근거 → 예상 → 비교 → 성공/중단 기준 → 결과 → 다음 결정`을 남긴다. 계획 상태는 `미착수 / 진행 중 / 검토 중 / 완료 / 보류`로 관리한다. 완료에는 근거 링크를 붙인다.

주간 점검은 커밋·테스트 개수 대신 닫은 질문, 바뀐 결론, 제품 반영, 남은 불확실성을 확인한다. 동시에 진행하는 구현·실험을 줄이고 하나의 검토 가능한 작업 단위로 마무리한다.

보류할 작업:

- 새로운 가설 없이 기존 폐기형 자기 정제의 규모·시드만 확대
- 다음 결정을 바꾸지 않는 임계값 미세 조정
- 결과를 본 뒤 성공 기준 변경
- 기존 평가 데이터를 반복 사용하며 독립 검증이라고 표현
- 사용자 필요가 확인되지 않은 대규모 서비스 기능
