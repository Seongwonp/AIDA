## 1. 문제 제기

*(hwpx 원문 그대로)*

AI 성능 저하의 원인은 항상 모델에 있지 않습니다

AI 성능이 기대에 미치지 못하면 일반적으로 모델 구조, 학습 방식, 하이퍼파라미터를
먼저 수정합니다. 그러나 객체탐지 모델은 학습데이터에 포함된 바운딩박스 위치 오류,
객체 누락, 잘못된 클래스와 같은 라벨 오류에도 민감하게 영향을 받습니다.

Schubert 등의 WACV 2024 연구에서는 BDD100K 객체탐지 학습데이터의 라벨 20%를
인위적으로 변형했을 때, 모델과 학습 조건이 동일함에도 mAP가 최대 3.9%p 감소했습니다.
이는 모델을 바꾸지 않아도 라벨 품질만으로 AI 성능이 유의미하게 하락할 수 있음을
보여줍니다.

또한 최근 연구에서는 객체 누락, 부정확한 바운딩박스와 같은 라벨 오류가 모델의
성능과 일반화 능력을 저하시킬 수 있으며, 품질이 낮은 재라벨링 과정은 기존 오류를
수정하기보다 오히려 새로운 오류를 더 많이 만들 수 있다고 지적합니다. 즉, 라벨
검수는 단순한 데이터 정리 작업이 아니라 모델 성능과 신뢰성을 결정하는 핵심 개발
단계입니다.(https://arxiv.org/abs/2508.06556)

**산업적으로 중요한 이유**

라벨 오류가 포함된 상태에서 성능이 낮아지면 기업은 실제 원인이 데이터에 있음에도
불구하고 모델 구조를 수정하거나 반복 학습을 수행할 수 있습니다. 그 결과 다음
문제가 발생합니다.

- 불필요한 모델 재학습과 GPU 비용 증가
- 잘못된 원인 분석으로 인한 개발 일정 지연
- 전체 데이터 재검수와 재라벨링 비용 발생
- 납품 데이터의 품질과 모델 성능에 대한 신뢰 저하

따라서 AI 개발 현장에서는 단순히 "라벨에 오류가 있는가"를 확인하는 것을 넘어,
성능 저하가 모델 때문인지 데이터 라벨 때문인지 구분하고, 어떤 오류가 성능에
얼마나 영향을 주는지 확인할 수 있는 검증 수단이 필요합니다.

## 2. 기존 방식의 한계

*(hwpx 원문 그대로)*

라벨 오류가 포함된 데이터로 AI 모델을 학습하면 모델 성능과 평가 결과가 저하될
수 있습니다. 이 경우 기업은 오류의 원인이 데이터에 있음에도 모델 구조나 학습
설정을 반복적으로 수정하고, 모델을 다시 학습한 뒤 데이터 재검수와 재라벨링까지
수행할 수 있습니다.

현재 데이터 품질검수는 자동화 도구를 활용하더라도, 오류 후보를 사람이 확인하고
기존 라벨을 검증·수정하는 절차가 필요합니다. 특히 대규모 데이터셋에서 오류가
발생한 위치와 유형을 특정하지 못하면 검수 범위를 넓게 잡아야 하므로, 많은 시간과
인력이 소요될 수 있습니다. AWS Ground Truth 역시 라벨 품질 확보를 위해 작업자가
기존 라벨을 반복적으로 검증하고 조정하는 구조를 제공하고 있습니다. 따라서 기존
방식은 성능 저하의 원인이 되는 오류 유형과 검수 대상을 빠르게 좁히기 어렵다는
한계점이 존재합니다.

이로 인해 1) 불필요한 모델 재학습과 GPU 사용 2) 데이터 재검수 및 재라벨링 3)
개발 일정 지연 4) 이미 완료된 데이터 구축 작업의 반복에 대한 비용이 발생할 수
있습니다.

## 3. AIDA 소개

*(hwpx 원문 그대로)*

"AIDA는 객체탐지 학습데이터의 라벨 오류 가능성과 모델 성능 영향을 분석하여,
재검수 우선순위와 품질검증 리포트를 제공하는 제3자 데이터 품질검증 플랫폼입니다."

AIDA: AI Data Integrity Diagnosis & Assurance

AIDA는 검증 대상 데이터셋을 오류 유형별 기준 성능 패턴과 비교하여 다음 정보를
제공합니다.

- 가능성이 높은 라벨 오류 유형
- 오류 수준에 따른 모델 성능 영향
- 우선 재검수 대상
- 데이터 품질검증 리포트

AIDA는 "오류가 있는가?"를 넘어 "어떤 오류가 성능에 영향을 주며, 어디부터 다시
봐야 하는가?"를 제시합니다.

## 4. 국방기술 활용 및 기술 원리

*(hwpx 원문 그대로)*

AIDA는 국방특허인 '가상 이미지 데이터 기반의 학습데이터 검증 기술'의 핵심 원리를
민간 AI 데이터 품질검증 분야에 적용한 서비스이다. 해당 국방특허의 핵심 원리는
'가상 오류 데이터 생성 → 오류 조건별 모델 성능 패턴 구축 → 실제 데이터와 비교하여
오류 가능성 추정' 구조이며 AIDA는 이를 자율주행 객체탐지 데이터 품질검증에 적용한
플랫폼이다. 초기 MVP에서는 KITTI Car 데이터셋의 기준 라벨에 IoU 기반으로 가로
길이, 세로 길이, 중심점 이동 오류를 주입하고, 동일한 YOLO 모델을 조건별로
학습·평가하여 오류 유형별 성능 패턴 DB를 구축한다. 이후 검증 대상 데이터셋의
성능 패턴을 기준 DB와 비교하여 가능성이 높은 오류 유형과 수준을 추정하고, 오류
후보, 성능 영향, 재검수 우선순위, 품질 리포트를 제공한다. 즉, AIDA는 데이터
오류를 자동 확정하는 시스템이 아니라, 성능에 영향을 줄 가능성이 높은 오류를
선별해 검수 범위를 줄여주는 데이터 품질검증 플랫폼이다.

*(이 섹션에는 이미 hwpx에 "국방 특허의 핵심 원리 ↔ AIDA의 자율주행 데이터
품질검증 적용" 2단 비교 인포그래픽이 들어가 있음 — 그대로 유지)*

## 5. MVP 구현 및 검증 계획

*(hwpx 원문 그대로 — 6번(결과물)과 합치지 말고 별개 섹션으로 유지)*

AIDA는 현재 아이디어 단계에 머무르지 않고, 실제 구현 가능성을 확인하기 위한
MVP를 구축했다. 공개 객체탐지 데이터셋(KITTI Car 클래스)을 기반으로 가로·세로
크기, 중심점 이동, 회전각, 스케일 등 오류 조건별 학습 데이터를 자동 생성하고,
동일한 초기 가중치·학습 조건에서 객체탐지 모델(YOLOv8n)을 21개 조건 전체 동일
50epoch로 반복 학습해 성능 변화를 실측했다.

그 결과 오류 유형과 강도에 따라 모델 성능이 서로 다르게 변화하는 패턴을 확인했다.
특히 회전각 오류가 가로·세로 오류보다 일관되게 크게 성능을 저하시켰고(mAP@0.5
최대 5.7%↓, Recall 최대 6.4%↓), Precision은 거의 변하지 않는 반면 Recall이 라벨
오류에 가장 민감하게 반응했다. 이 결과는 표와 그래프로 정리해 조건별 성능
데이터를 비교할 수 있는 구조로 구현했다.

다만 현재 결과는 조건당 1회 실행(단일 시드)에 기반하므로, 이 패턴이 순수한 오류
효과인지 학습 과정의 노이즈인지는 통계적으로 완전히 분리되지 않는다. 본선 진출
시 조건당 복수 시드 반복으로 통계적 유의성을 검증할 계획이다.

초기 웹 대시보드는 데이터셋 품질점수, ROI 절감 추정, 오류 조건별 성능 변화
그래프, 조건별 상세 지표(mAP·Precision·Recall·IoU 감소율), 재검수 우선순위, CSV
다운로드를 한 화면에서 제공하도록 구성했다. 이 화면은 실제 실험 결과
(metrics.csv)를 그대로 반영하며, 코드 수정 없이 결과가 갱신되는 구조다. 향후에는
실제 고객 데이터셋 업로드 기능과 사용자 피드백을 반영해 UI를 고도화할 계획이다.

**MVP의 핵심 구성**

1. 오류 데이터 생성 모듈
   기준 바운딩박스에 통제된 오류를 자동으로 주입하고, 오류 유형과 강도별 학습
   데이터셋을 생성한다.

2. 모델 학습·평가 모듈
   각 오류 조건에서 동일한 초기 가중치와 학습 조건을 적용하여 객체탐지 모델을
   학습하고, mAP, Precision, Recall 등의 성능지표를 수집한다.

3. 성능 패턴 데이터베이스
   오류 유형과 강도에 따른 성능 변화를 저장하여, 검증 대상 데이터셋과 비교할 수
   있는 기준 패턴을 구축한다.

4. 오류 가능성 분석 모듈
   기준 패턴 데이터베이스를 활용해 오류 유형별로 가장 큰 성능 저하를 보이는
   조건을 찾아 재검수 우선순위(높음/중간/낮음)를 매긴다. 현재는 기준 패턴 자체를
   진단 예시로 제공하는 단계이며, 실제 고객 데이터셋을 업로드해 그 성능 벡터를
   기준 패턴과 비교·매칭하는 기능은 다음 단계 구현 대상이다.

5. 품질검증 대시보드
   데이터셋 품질점수, 오류 의심 건수, 성능 변화, 우선 재검수 대상을 시각적으로
   제공한다.

## 6. 결과물

*(hwpx 원문 그대로)*

AIDA의 결과물은 데이터셋 품질점수, 오류 유형별 진단 리포트, 재검수 우선순위,
그리고 납품용 품질 인증서 초안 네 가지로 구성된다.

품질점수는 데이터셋 전체의 신뢰도를 0~100점으로 요약한 값이다. 일정 기준을
충족하면 품질 인증서 발급 대상이 되며, 기준 미달 시 "검토 필요" 상태로 표시된다.

오류 유형별 진단 리포트는 가로·세로 크기, 중심점 이동, 회전각, 스케일 등 오류
유형마다 기준 패턴 대비 최대 성능 저하율을 계산하고, 이를 근거로 재검수
우선순위(높음/중간/낮음)를 매긴다. 실측 결과 기준으로는 회전각 오류가 가장 큰
저하(mAP@0.5 5.7%↓)를 보여 재검수 우선순위가 가장 높게 나타났다. 다만 이 값은
100% 확정 진단이 아니라 확률적 추정이며, "재검수 자원을 어디에 먼저 투입할지"를
안내하는 가이드로 제공된다.

영향 지표로는 mAP@0.5, mAP@0.5:0.95, Precision, Recall 네 가지를 조건별로 함께
제시한다. 특히 Precision은 오류 조건에서도 거의 변하지 않는 반면 Recall은
뚜렷하게 하락해, 라벨 오류가 "오탐 증가"보다 "미탐 증가"로 먼저 나타난다는 점을
실측으로 확인했다. 여기에 원본 라벨과의 평균 IoU 감소율을 더해, 단순 퍼센트
강도보다 객관적인 오류 강도 지표를 함께 제공한다.

품질 리포트 예시는 위 항목들을 하나의 화면(대시보드) 또는 문서로 정리한
산출물이다. 데이터셋 기본 정보, 품질점수, 조건별 성능 변화 그래프, 오류 유형별
우선순위 표, 그리고 도입 시 절감 가능한 재검수 비용·GPU 재학습 비용 추정치(예시
시나리오 기준)를 함께 제공해, 발주처가 "왜 이 데이터셋을 재검수해야 하는지"를
근거와 함께 확인할 수 있도록 한다.

## 7. 고객 구조/수요

AIDA의 1차 고객은 객체탐지 학습데이터를 발주하는 자율주행·모빌리티 비전 AI
기업과 완성차·부품사, 그리고 공공 AI 데이터 구축기관이다. 이들은 라벨링 업체로부터
데이터를 납품받지만, 실제 모델 성능이 낮아졌을 때 원인이 모델에 있는지 라벨에
있는지 구분할 근거가 없다는 문제를 안고 있다. AIDA는 이 발주처·AI 개발사에게
납품 데이터의 오류 가능성과 재검수 우선순위를 제시해, 무엇을 다시 검수해야 하는지
판단할 근거를 제공한다.

라벨링·데이터 구축 업체는 AIDA의 두 번째 고객이자 협력자다. 이들은 발주처가
요구하는 납품 조건을 충족해야 하는 입장이므로, 납품 전 AIDA의 품질검증 리포트를
제출해 품질을 스스로 증명하고 재작업 범위를 줄일 수 있다. 공공 AI 데이터 구축
사업에서는 이 수요가 이미 제도적으로 존재한다. 한국지능정보사회진흥원(NIA)이
주관하는 AI 학습용 데이터 구축사업은 TTA 품질지표 기준서에 따라 바운딩박스
정확도 등 정량 기준을 요구하고, 기준서 자체가 '제3자 품질검증'을 별도 절차로
명시하고 있다. AIDA는 이 기존 절차에 들어맞는 도구로 설계되어 있어, 새로운
시장을 만드는 것이 아니라 이미 존재하는 품질검증 수요에 맞춰 들어가는 구조다.

## 8. 사업 모델

AIDA의 수익 구조는 단발성 검증에서 반복 계약으로 단계적으로 확장한다. 초기에는
검증 대상 데이터셋의 규모와 객체 수를 기준으로 1회 품질검증 수수료를 받는다.
이는 발주처가 모델 재학습 1회에 들이는 비용보다 낮게 책정해 도입 문턱을 낮추는
것을 목표로 한다. 검증이 끝나면 납품용 품질 리포트와 인증서 초안을 별도
산출물로 제공하고, 이 리포트 발급에 추가 과금을 적용한다.

반복적으로 데이터셋을 검수해야 하는 고객에게는 프로젝트 단위 계약이나 API 연동
계약으로 전환한다. 발주처는 데이터 파이프라인에 AIDA API를 연동해 납품 시점마다
자동으로 품질검증을 받을 수 있고, AIDA는 이를 통해 건별 과금에서 사용량 기반
구독형 과금으로 수익 구조를 옮겨간다. 검증 수수료 → 리포트 과금 → API/프로젝트
계약으로 이어지는 이 구조는 고객이 AIDA를 처음 접하는 시점부터 장기 계약으로
전환되는 시점까지 자연스럽게 연결되도록 설계했다.

## 9. 시장성/성장 전략

AIDA는 객체탐지 라벨 구조가 이미 표준화되어 있는 자율주행·ADAS 분야에서
시작한다. KITTI, BDD100K와 같은 공개 데이터셋과 동일한 바운딩박스 포맷을 쓰는
시장이기 때문에, MVP에서 검증한 오류 조건별 성능 패턴을 큰 수정 없이 적용할 수
있다. 이후에는 공공 AI 데이터 구축사업으로 고객군을 넓히고, 같은 방식의
객체탐지 라벨을 쓰는 로봇비전, 스마트팩토리·CCTV 영상분석, 국방·항공 분야로
순차 확장한다.

성장 경로는 4단계로 나눠 추진한다. 먼저 자체·공개 데이터셋으로 오류 진단
엔진과 품질 리포트 양식을 검증하는 기술검증기를 거치고, AI 개발사 대상 샘플
리포트와 소규모 PoC로 고객 레퍼런스를 확보하는 초기시장 진입기로 넘어간다.
이어 공공 AI 데이터구축기관, 스마트팩토리, CCTV 영상분석 기업으로 고객군을
넓히는 성장기를 거쳐, 라벨링·구축 기업이 발주처 요구에 따라 AIDA 검증 리포트를
상시 발급받는 확장기로 이어진다. 도메인이 늘어날수록 오류 패턴 DB도 함께
쌓이므로, 뒤에 진입하는 산업일수록 검증 정확도가 앞선 산업의 데이터로 보강되는
구조다.

## 10. 리스크 대응

AIDA가 안고 있는 기술적 한계는 세 가지이며, 숨기지 않고 본선 전 개선 계획으로
설명한다.

첫째, 회전각 오류 조건의 기하학적 한계다. 현재 MVP는 일반 YOLOv8 모델과 KITTI
2D 라벨을 그대로 쓰기 때문에, 기울어진 박스를 축정렬(AABB) 외접 박스로 근사해서
학습한다. 이를 보완하기 위해 박스 크기는 그대로 두고 중심점만 이동시키는 조건과,
중심은 그대로 두고 크기만 바꾸는 스케일 조건을 독립 변수로 추가해 회전 오차에
섞여 있던 위치·크기 효과를 분리해 검증했다. 본선 이전에는 기울어진 라벨을 그대로
학습하는 OBB(Oriented Bounding Box) 모델과 Rotated IoU 평가지표 도입을 검토한다.

둘째, 확정 진단의 한계다. 라벨 오류를 100% 역추정하는 것은 원리적으로 불가능한
문제다. AIDA는 이를 인정하고 완벽한 자동 판정 도구가 아니라, 성능에 영향을 줄
가능성이 높은 오류 후보를 좁혀 재검수 우선순위를 제시하는 확률적 가이드로
포지셔닝한다. 사람의 최종 검토를 대체하는 것이 아니라, 기존 검수 체계를 보완하는
자체 QA 보완재로서 검토 범위를 줄여주는 도구라는 점을 리포트와 대시보드에
일관되게 명시한다.

셋째, 단일 시드 실험의 한계다. 2차 예선까지의 실험은 조건당 1회 학습으로
방향성을 검증하는 수준이며, 본선 전에는 복수 시드 반복 실험과 실제 고객
데이터셋 PoC로 통계적 신뢰도를 보강할 계획이다.

## 11. 팀 역량/실행계획

팀은 4명으로 구성되어 있고, 역할이 겹치지 않게 나뉘어 있다. 박성원(수원대학교
정보보호학과)은 대표로서 백엔드·인프라와 실험 결과 연동, 문서화를 맡는다.
김해연(영남대학교 전자공학과)은 KITTI·YOLO 실험 설계와 결과 해석을 담당한다.
서정호(대구가톨릭대학교 반도체전자공학과)는 데이터 파이프라인과 서비스 구조를,
정경준(고려대학교 기계공학부)은 React 기반 대시보드와 시각화를 맡는다. 이 역할
분담은 이미 동작하는 MVP(FastAPI 백엔드, React 대시보드, KITTI 21개 조건 실험
파이프라인)로 증명되었다.

실행 계획은 본선(2026년 7월 31일)을 기준으로 시기별로 짰다. 본선 전에는
OBB 도입 검토, 복수 시드 반복 실험, 대시보드 상세표·CSV 다운로드 고도화에
집중한다. 2026년 3분기에는 자율주행 샘플 데이터셋으로 첫 PoC를 진행하고 품질
리포트 양식을 다듬으며, 4분기에는 베타를 론칭해 라벨링 업체·AI 개발사를 대상으로
파일럿을 운영한다. 2027년 상반기에는 유료 검증 계약과 API 과금 전환을 목표로
한다. 초기 자금은 경진대회 MVP 지원금 50만 원, 대표자 초기 자본 50만 원에 AWS
Activate Founders 크레딧($1,000 상당), GCP 무상 크레딧($300 상당)을 더해
확보했고, 2026년 4분기 예비창업패키지 연계로 최대 1,000만 원의 추가 자금을
준비하고 있다.

## 12. 마무리

AIDA는 이미 납품된 객체탐지 라벨을 다시 만드는 서비스가 아니라, 그 라벨이 모델
성능에 실제로 어떤 영향을 주는지 검증하는 제3자 품질검증 플랫폼이다. 국방과학
연구소 특허의 가상 오류 데이터 생성 원리를 민간 객체탐지 데이터에 적용해 21개
오류 조건의 실측 성능 패턴 DB를 구축했고, 이를 대시보드와 리포트로 이어 발주처가
재검수 우선순위를 스스로 판단할 수 있게 했다. 완벽한 자동 판정을 약속하지 않는
대신, 지금보다 더 빠르고 근거 있는 재검수 의사결정을 돕는 것이 AIDA가 만들고자
하는 가치다.
