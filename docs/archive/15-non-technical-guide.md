# 15. 비전공자 팀원용 설명서 — 테스트 결과와 프로그램 흐름
<!-- 시점 표시 -->

> **끝난 일의 기록이다.** 2026 국방기술 창업경진대회는 2026-08-19에 2차 예선에서 탈락했고, 그 뒤로 프로젝트는 발표 준비가 아니라 기술 검증으로 방향을 바꿨다. 이 문서는 **당시 상태 그대로 두며 갱신하지 않는다** — 지금 시스템과 다른 것이 정상이다. 현재 상태는 저장소 README와 [21-next-plan.md](./21-next-plan.md)를 볼 것.


이 문서는 개발자가 아닌 팀원이 AIDA를 설명할 수 있도록 만든 쉬운 버전이다.
발표, 멘토링, 팀 내부 공유 때는 이 문서를 먼저 보고, 더 자세한 수치가 필요하면
[12-experiment-results.md](./12-experiment-results.md)를 보면 된다.

## 1. AIDA를 한 문장으로 설명하면

**AIDA는 AI가 학습할 데이터의 라벨이 얼마나 믿을 만한지 검사하고, 어떤 종류의
라벨 오류를 먼저 고쳐야 하는지 알려주는 데이터 품질 점검 프로그램이다.**

여기서 말하는 라벨은 사진 속 자동차 위치를 네모 박스로 표시한 정답표라고 보면 된다.
예를 들어 자동차가 있는 위치보다 박스가 너무 넓거나, 너무 짧거나, 약간 비틀려 있으면
AI는 잘못된 정답을 보고 공부하게 된다. AIDA는 이런 문제가 AI 성능에 어떤 영향을
주는지 실험하고, 그 결과를 대시보드로 보여준다.

## 2. 이번에 끝난 테스트는 무엇인가

이번 테스트는 **자동차 이미지 데이터에 일부러 여러 종류의 라벨 오류를 넣고, AI 모델의
성능이 얼마나 떨어지는지 확인한 실험**이다.

실험 조건은 다음과 같다.

| 항목 | 내용 |
|---|---|
| 사용 데이터 | KITTI 자동차 이미지 |
| 학습 이미지 | 400장 |
| 평가 이미지 | 120장 |
| AI 모델 | YOLOv8n |
| 학습 횟수 | 13개 조건 모두 동일하게 50epoch |
| 오류 비율 | 전체 라벨 중 30%에만 오류 주입 |
| 실행 환경 | Windows 데스크탑, NVIDIA RTX 3050 |

중요한 점은 **모든 조건을 같은 기준으로 다시 돌렸다는 것**이다. 그래서 특정 조건만
학습을 더 오래 해서 유리해지는 문제를 줄였다.

## 3. 테스트는 끝났는가

끝난 상태로 보면 된다.

`experiment/run_full.log`의 마지막에 아래 흐름이 남아 있다.

1. 50epoch 학습 완료
2. 가장 좋은 모델 파일 저장
3. 검증 결과 저장
4. `metrics.csv` 갱신
5. 전체 완료 메시지 출력

최종 결과 파일은 아래 위치에 반영되어 있다.

```text
C:\Users\USER\Desktop\AIDA\backend\app\data\metrics.csv
```

즉, 실험 결과가 이미 백엔드와 프론트엔드 대시보드에서 읽을 수 있는 형태로 저장되어 있다.

## 4. 핵심 테스트 결과

기준이 되는 정상 데이터(`clean`)의 성능은 다음과 같다.

| 기준 데이터 | mAP@0.5 | Precision | Recall |
|---|---:|---:|---:|
| clean | 0.876 | 0.859 | 0.795 |

쉽게 말하면, 정상 라벨로 학습했을 때의 성능을 100점짜리 기준선으로 두고,
오류가 들어간 라벨에서는 성능이 얼마나 떨어지는지 비교한 것이다.

### 가장 큰 영향을 준 오류

가장 성능을 크게 떨어뜨린 오류는 **회전각 오류**였다.

| 조건 | 의미 | mAP@0.5 | 정상 대비 성능 저하 |
|---|---|---:|---:|
| `rot_m15` | 박스가 -15도 방향으로 틀어진 경우 | 0.826 | 5.7% 하락 |
| `rot_p15` | 박스가 +15도 방향으로 틀어진 경우 | 0.837 | 4.5% 하락 |

비전공자용 해석:

**자동차를 감싸는 네모 박스가 기울어진 상황을 축정렬 네모 박스로 근사했을 때,
AI 성능이 더 크게 떨어지는 경향이 보였다.** 다만 현재 실험은 진짜 기울어진 박스(OBB)를
쓴 것이 아니라, 회전된 박스를 다시 수평/수직 네모로 감싼 방식이다. 그래서 "회전각
오류를 완전히 해결했다"가 아니라 "현재 2D 박스 구조에서 회전 오류를 근사했을 때의
한계를 확인했다"라고 말해야 한다.

### 가로/세로 크기 오류는 상대적으로 영향이 작았다

| 조건 | 의미 | 정상 대비 성능 저하 |
|---|---|---:|
| `width_p30` | 가로가 30% 더 넓은 박스 | 2.4% 하락 |
| `width_m30` | 가로가 30% 더 좁은 박스 | 1.5% 하락 |
| `height_p15` | 세로가 15% 더 긴 박스 | 0.9% 하락 |
| `height_p30` | 세로가 30% 더 긴 박스 | 0.6% 하락 |

비전공자용 해석:

**박스가 조금 크거나 작은 정도는 AI가 어느 정도 버틸 수 있었다. 하지만 박스가
비틀리는 오류는 더 민감하게 반응했다.**

## 5. 결과를 말할 때 조심해야 할 점

이번 결과는 의미가 있지만, 발표에서 너무 단정적으로 말하면 안 된다.

좋은 표현:

> 이번 실험에서는 회전각 오류가 가로/세로 크기 오류보다 성능 저하에 더 큰 영향을
> 주는 경향을 확인했습니다.

피해야 할 표현:

> 회전각 오류가 항상 제일 나쁩니다.

왜냐하면 이번 실험은 조건당 1번씩만 실행했기 때문이다. AI 학습은 무작위 요소가 있어
같은 조건도 여러 번 돌리면 수치가 조금 달라질 수 있다. 따라서 지금은 **방향성을 확인한
실험**이고, 본선이나 후속 연구에서는 여러 번 반복해서 평균을 내면 더 설득력이 커진다.

## 6. 프로그램은 어떻게 돌아가는가

AIDA는 크게 세 부분으로 나뉜다.

| 폴더 | 역할 | 쉬운 설명 |
|---|---|---|
| `experiment/` | 실험 파이프라인 | 데이터를 만들고 AI를 학습시켜 결과표를 만든다 |
| `backend/` | API 서버 | 결과표를 읽어서 프론트엔드가 이해할 수 있는 형태로 전달한다 |
| `frontend/` | 대시보드 | 사용자가 볼 수 있는 화면을 보여준다 |

전체 흐름은 다음과 같다.

```text
이미지 데이터 준비
  -> 일부 라벨에 오류 주입
  -> 조건별로 AI 모델 학습
  -> 성능 측정
  -> metrics.csv 저장
  -> 백엔드가 CSV 읽기
  -> 프론트엔드 대시보드에 표시
```

## 7. 실험 파이프라인 흐름

`experiment/`는 실제 테스트 결과를 만드는 부분이다.

1. `download_kitti.py`
   KITTI 자동차 이미지와 라벨 데이터를 준비한다.

2. `data_loader.py`
   원본 데이터 중 실험에 쓸 자동차 데이터만 골라 정리한다.

3. `error_injector.py`
   정상 라벨 일부에 일부러 오류를 넣는다.
   예를 들어 가로를 30% 줄이거나, 세로를 15% 늘리거나, 박스를 15도 회전시킨다.

4. `train.py`
   오류 조건별 데이터로 YOLOv8n 모델을 학습시킨다.

5. `evaluate.py`
   학습된 모델이 평가 이미지에서 자동차를 얼마나 잘 찾는지 측정한다.

6. `run_all.py`
   위 과정을 13개 조건에 대해 한 번에 실행하고, 최종 결과를 CSV로 저장한다.

## 8. 백엔드는 무엇을 하는가

백엔드는 `backend/app/data/metrics.csv`를 읽어서 세 가지 API로 나눠준다.

| API | 역할 |
|---|---|
| `/api/summary` | 전체 품질 점수, 이미지 수, 객체 수, 오류 의심 건수 제공 |
| `/api/conditions` | 13개 조건별 성능 수치 제공 |
| `/api/diagnose` | 어떤 오류 유형을 먼저 재검수해야 할지 우선순위 제공 |

쉽게 말하면 백엔드는 **엑셀 표처럼 저장된 실험 결과를 대시보드가 보기 좋은 데이터로
바꿔주는 중간 전달자**다.

## 9. 프론트엔드는 무엇을 보여주는가

프론트엔드는 사용자가 보는 웹 화면이다.

화면에서 보여주는 내용은 다음과 같다.

| 화면 요소 | 의미 |
|---|---|
| 데이터셋 품질 점수 | 현재 샘플 데이터의 품질을 100점 기준으로 표시 |
| 오류 조건별 성능 저하 그래프 | 어떤 오류 조건에서 AI 성능이 얼마나 떨어지는지 표시 |
| 조건별 상세 지표 표 | mAP, Precision, Recall, 평균 IoU, IoU 감소율을 조건별로 표시 |
| ROI 추정 카드 | 수작업 검수와 GPU 재학습 비용이 얼마나 줄 수 있는지 가정값으로 표시 |
| CSV 다운로드 | 조건별 결과를 파일로 내려받기 |
| 재검수 우선순위 표 | 어떤 라벨 오류를 먼저 확인해야 하는지 안내 |

현재 대시보드는 "확정 판정"이 아니라 **재검수를 어디부터 해야 할지 알려주는 가이드**로
설계되어 있다.

ROI 카드는 실제 고객 계약 금액이 아니라 발표용 추정 예시다. 예를 들어 라벨 10만 건을
전부 사람이 다시 보는 대신, AIDA가 의심 라벨 30%를 먼저 고르게 해준다고 가정한다.
그러면 재검수 범위가 70% 줄어들고, 불필요한 GPU 재학습 횟수도 줄어든다는 식으로
비용 절감 효과를 계산한다.

## 10. 주요 용어를 쉽게 설명하면

| 용어 | 쉬운 뜻 |
|---|---|
| 라벨 | 이미지 속 자동차 위치를 표시한 정답 정보 |
| 바운딩박스 | 자동차를 감싸는 네모 박스 |
| 객체탐지 | 이미지에서 자동차 같은 물체를 찾아 위치까지 표시하는 AI 기술 |
| YOLOv8n | 빠르고 가벼운 객체탐지 AI 모델 |
| mAP@0.5 | AI가 물체를 얼마나 잘 찾았는지 보는 대표 점수 |
| IoU | 두 네모 박스가 얼마나 겹치는지 보는 비율 |
| IoU 감소율 | 오류를 넣은 뒤 정답 박스와 얼마나 덜 겹치게 됐는지 보는 값 |
| Precision | AI가 자동차라고 한 것 중 실제 자동차가 얼마나 많았는지 |
| Recall | 실제 자동차 중 AI가 얼마나 놓치지 않고 찾았는지 |
| epoch | 같은 학습 데이터를 몇 번 반복해서 공부했는지 |
| clean | 오류를 넣지 않은 정상 기준 데이터 |

## 11. 팀원이 기억하면 좋은 결론

1. 테스트는 완료되었고 결과는 `metrics.csv`에 반영되어 있다.
2. 정상 기준 성능은 mAP@0.5 기준 0.876이다.
3. 가장 큰 성능 저하는 `rot_m15` 조건에서 나타났고, 정상 대비 5.7% 하락했다.
4. 단, 회전각 조건은 진짜 OBB가 아니라 축정렬 박스 근사이므로 한계를 함께 설명해야 한다.
5. AIDA는 오류를 100% 확정하는 도구가 아니라, 재검수 우선순위를 잡아주는 도구다.
6. 현재 결과는 조건당 1회 실행이므로, 후속 단계에서는 반복 실험으로 신뢰도를 높이면 좋다.
