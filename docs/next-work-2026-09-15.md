### W3 — 최소 구현 (Claude, W2 뒤)

**고른 질문에 필요한 것만 만든다.** 아래는 Q-A 기준이다. 다른 질문이면 위 표의 "필요한 구현"만.

1. **진단이 모든 기존 라벨의 `label_iou`를 쓴다.** 지금 결과 파일에는 규칙에 걸린 후보만 있다.
   이미지·라벨 번호·클래스·가장 많이 겹치는 예측과의 IoU를 라벨마다 한 줄. 순수 부분은 `label_diagnosis.py`에,
   검사는 `experiment/tests`.
2. **평가 묶음에 `all_label_iou` 방법과 무작위 라벨 표본 층.** 판정 대상 = 방법별 상위 N 합집합 ∪ 무작위 K.
   무작위로 뽑혔다는 사실을 후보마다 기록하고, 합집합과 겹치면 **한 번만** 판정한다.
3. **예산 규칙을 코드와 사전 등록에 같이 적는다.** AIDA 후보가 N보다 적을 때 남는 예산을 어떻게
   셀지(안 쓴 예산으로 두는가), AIDA 후보가 아닌 라벨을 AIDA 순서에서 어떻게 다루는지. **판정 전에**
   정하고 결과를 보고 바꾸지 않는다.
4. 무작위 표본 층의 집계: AIDA 후보 밖 라벨의 판정 오류 비율과 구간. 방법 간 비교에 섞지 않는다.
5. 검사는 **손으로 만든 진단 결과**로. 고치기 전에 실패하는 검사를 먼저 확보한다.

만들지 않는 것: 판정자 ID·이중 판정(둘째 판정자가 생기기 전), v1·v2 이중 동결(Q-B가 아니면),
새 순위 공식·문턱 조정.

완료: backend·experiment·frontend 검사 통과, [evaluation-adjudication-design.md](evaluation-adjudication-design.md)와
[testing-boundary.md](testing-boundary.md)에 새 규칙과 경계를 적는다.

**결과 (2026-09-16).** 커밋 `218f9bdf`(진단), `344041c8`(평가).

|---|---|
| 모든 기존 라벨의 `label_iou`, 필터 전 미매칭 예측(확신도·삼켜짐) | `label_diagnosis.label_rows`·`unmatched_prediction_rows`, 진단 결과의 `all_labels`·`unmatched_predictions` |

| N·K·씨앗 | 판정량 상한은 `(기존 라벨 층 방법 수) × N + (누락 층) N + K` |
| 1차 지표·Δ 방침 | Δ가 없으면 prelim1처럼 성공·실패를 판정하지 않는다고 적는다 |
| 연속 프레임 묶음(`group_id`) 규칙 | 주행 영상이면 필요. 지금 내보내기는 늘 비어 있다 — 쓰려면 W3에 넣는다 |
| 판정자 | 1인이면 "탐색"으로 적는다 |

대용량 다운로드는 **용량·시간을 먼저 적고 사용자 승인 후** 받는다.

### W6 — 판정 [사용자]

prelim1 순서 그대로: 업로드·진단 → 파일 점검(`all_candidates` 등) → 묶음 고정 → **별도 점검용 평가로**
가림 화면 확인 → 두 묶음으로 나눠 판정 → 마지막 판정 뒤 기록 전송 확인(185 대 186 사례).

### W7 — 집계·감사·결과 (Claude)

[prelim1-results.md](prelim1-results.md) 형식: 사전 등록 6절 그대로 집계, 독립 산술 감사, 판정·기록 대조,
"말하지 않는 것" 절. 결과가 불리해도 순서·문턱을 이 데이터로 다시 세지 않는다.
