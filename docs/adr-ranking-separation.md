# ADR — 데이터셋 진단과 후보 재검수 순위를 분리한다

| | |
|---|---|
| 상태 | **채택 (2026-09-14, 사용자 결정)** — 구조 방향만. 새 순위 v2는 **검증되지 않은 시험 버전**이다 |
| 선택 | [prelim1-decision.md](prelim1-decision.md)의 **C안**을 구조로, **A안**을 v2 기존 라벨 후보 순서의 가장 단순한 임시안으로 |
| 버린 안 | B(승격 상한) — prelim1을 보고 상한을 고르게 되어 과적합 위험이 높다. D(학습) — 판정 오류 18건으로는 너무 작다 |

## 1. 두 질문은 다르다

| 질문 | 답하는 것 | 단위 |
|---|---|---|
| **데이터셋 진단** | "이 데이터셋에 어떤 유형의 오류가 계통적으로 많아 보이는가" | 데이터셋 |
| **재검수 우선순위** | "지금 어느 후보부터 사람이 볼 것인가" | 후보 하나 |

데이터셋 수준 증거(유형별 지목 비율)는 **흔한 오류 유형**을 말해 줄 수 있다. 그러나 그것이
**그 유형의 후보 하나하나가 오류일 확률**을 말해 주지는 않는다. 지목이 많은 까닭이 라벨
오류일 수도, 자(기준 모델)의 편향일 수도 있다.

**그래서 데이터셋 진단이 그 유형의 모든 후보를 자동으로 위로 올리지 않는다.**

## 2. 이 결정을 떠민 증거 — 검증이 아니다

prelim1([prelim1-results.md](prelim1-results.md), 판정자 1인·KITTI Car 300장):

- 절대 문턱을 넘은 유형이 없었는데 상대 문턱으로 width가 계통 유형이 됐고, **현재 제품 순위의
  상위 90건이 전부 width**였다.
- N=90에서 판정상 고유 오류가 **현재 제품 순위 4건, 단순 IoU 불일치 순서 14건**이었다.

이것은 **분리를 떠민 개발 증거**다. v2가 낫다는 증거가 **아니다**.

- prelim1은 **소비된 개발 데이터**다([evaluation-data.md](evaluation-data.md) 원장). v2를 prelim1로
  다시 세지 않는다 — 결과를 보고 고른 순서를 같은 데이터로 재면 아무것도 보여 주지 않는다.
- v2의 기존 라벨 순서는 prelim1의 기준선과 **같은 신호**(`1 − label_iou`)다. 그러니 AIDA 후보 안에서
  "v2 대 IoU 기준선"을 견주면 같은 순서끼리 견주게 된다. **v2에 IoU를 쓰는 것은 제품 부품으로
  쓰는 것이지 AIDA가 기준선을 이겼다는 뜻이 아니다.** 그래서 v2 묶음은 내보내기와 집계에서
  `iou_baseline`과 견주지 못하게 막는다(2026-09-14) — 같은 순서끼리 견주면 차이가 0에 가깝게 나와
  대등한 것처럼 읽힌다. v2 이후 AIDA만의 몫은 순서가 아니라 후보 생성·유형 설명·누락 탐지·데이터셋 요약이다.

## 3. 결정

### 순위 버전

| ID | 무엇 | 상태 |
|---|---|---|
| `aida_v1_systematic_boost` | 지금까지의 제품 순위. 계통 유형 후보를 통째로 먼저, 그 안에서 심각도 순. 데이터셋 판정으로 심각도도 다시 매긴다 | **기본값 유지.** 뜻을 바꾸지 않는다 |
| `aida_v2_candidate_iou` | 층마다 후보 단위 신호만 쓴다 | **시험 버전.** 고를 때만 쓴다 |

버전 기록이 없는 옛 결과·묶음·내보내기는 **v1**이 만든 것으로 읽는다 — v2 전에는 v1 하나뿐이었다.
옛 v1 결과를 v2라고 고쳐 부르지 않는다.

### v2의 층

| 층 | 순서 신호 | 동점 |
|---|---|---|
| **기존 라벨 후보** | `1 − label_iou` 내림차순. `label_iou`가 없으면 **점수를 지어내지 않고 멈춘다** | 이미지 이름 → 라벨 번호 → 의심 유형 |
| **누락 후보** | 기존 신호(심각도) 내림차순 | 이미지 이름 → 상자 좌표 |

- 두 층의 점수는 **다른 신호라 크기를 비교하지 않는다.** 한 줄 목록이 필요한 화면을 위해
  층 순위를 번갈아 놓는다(기존 1, 누락 1, 기존 2, …) — 이것은 **표시 규칙**이고 평가하지 않았다.
- v2는 데이터셋 판정으로 심각도를 다시 매기지 않는다(그것도 승격이다).
- 유형별 상수를 새로 넣지 않고, 문턱을 prelim1로 조정하지 않는다.

### 데이터셋 진단은 그대로 낸다

유형별 비율, 계통 유형(절대·상대 문턱 중 무엇으로 잡혔는지), 상대 문턱이 기하 유형만 올렸다는
경고. **v2에서는 이것이 후보 순서를 바꾸지 않는다**고 결과와 화면에 적는다.

### 계약에 드러낸다

진단 결과·API 응답·평가 묶음·내보내기에 `ranking_version`, `ranking_scope`, `ranking_signal`,
`dataset_boost_affects_order`, `tie_break_rule`을 싣는다.

- 진단 결과는 **버전마다 다른 파일**에 쓴다. 다른 버전의 결과가 있는 자리에는 쓰지 않는다.
- 새 평가 묶음은 순위 버전을 얼리고 지문에 넣는다. **옛 묶음의 지문은 바뀌지 않는다**
  (버전이 없으면 지문 재료에 넣지 않는다) — prelim1은 v1에 묶여 있다.
- 순위 버전이 다른 내보내기를 한 집계에 섞으면 **거부한다.**

## 4. 이 결정이 말하지 않는 것

- 누락 후보는 비교군이 없어 **별도 기술 통계 층**으로 남는다. prelim1의 22/24는 개발자 판정이고
  비교군이 없다.
- **후보 생성은 평가되지 않았다.** 판정한 것은 두 순서 상위 90의 합집합뿐이다. AIDA가 만들지
  않은 후보(규칙에 안 걸린 라벨)의 오류는 보지 않았다.
- 제품 전체의 가치는 **AIDA 후보 안의 재정렬**이 아니라 후보 생성과 검수 흐름까지 넣은 새 평가가
  있어야 말할 수 있다 — [next-evaluation-proposal.md](next-evaluation-proposal.md).

## 5. 뒤집을 조건

손대지 않은 데이터셋에서 사전 등록한 비교가 v2의 기존 라벨 순서를 v1보다 낫지 않다고
보이면, 기본값을 바꾸지 않은 채 이 ADR을 다시 연다. 그 반대여도 **기본값 전환은 따로 사용자가
정한다.**
