# prelim1 이후 제품 해석과 선택지

> 사전 등록한 1차 탐색 비교(N=90)에서 **현재 제품 순서가 단순 IoU 불일치 기준선보다
> 나빴다.** 이 문서는 그 결과가 무엇을 말하고 무엇을 말하지 않는지 나누고, 다음
> 선택지를 **고르지 않고** 늘어놓는다. 결정은 사용자가 한다.

## 1. 무엇이 평가됐고 무엇이 안 됐나

| 영역 | 상태 | 근거 |
|---|---|---|
| **후보 생성** | **평가 안 됨** | 판정은 두 방법 상위 90의 합집합뿐이다. AIDA 규칙이 만들지 않은 라벨(규칙에 안 걸린 오류)이나 판정 밖 후보는 보지 않았다 |
| **기존 라벨 후보 순위** | **기준선보다 나빴다 (prelim1, N=90)** | AIDA 제품 순서 고유 오류 4건, 기준선 14건, 차이 −10, 이미지 묶음 짝지은 부트스트랩 95% 구간 [−18, −2]. Δ가 없어 공식 성공 기준은 없지만 **관측된 방향은 불리하다** |
| **누락 후보 탐지** | 기술 통계만 | 24건 중 22건을 오류로 판정. 비교군이 없다 |
| **절대 정확도** | **없음** | 판정자 1인(개발자), 합의된 정답 없음. 판정은 정답이 아니다 |
| **일반화** | **없음** | KITTI Car 개발 표본 300장, 자 하나 |

**누락 후보의 좋은 숫자가 기존 라벨 비교의 실패를 상쇄하지 않는다.** 두 층은 비교
조건이 다르고(누락 층은 비교군이 없다), 합쳐서 하나의 제품 판정을 만들지 않는다.

## 2. 다음 선택지 — 구현하지 않았다

실패 분석([prelim1-failure-analysis.md](prelim1-failure-analysis.md))의 가설과
연결되지만, **어느 안도 prelim1로 검증할 수 없다.** prelim1은 소비된 개발 데이터다.

### A. 기존 라벨 후보를 IoU 불일치로 직접 줄 세운다

| | |
|---|---|
| 기대 이득 | prelim1에서 관측상 더 많이 찾은 순서를 그대로 쓴다. 단순하고 설명하기 쉽다 |
| 위험 | 유형 정보(어떤 오류인지)가 순서에서 빠진다. 누락 후보에는 쓸 수 없다. AIDA 규칙의 가치가 "후보 생성"에만 남는다 |
| prelim1 근거 | 상위 90에서 14 대 4. 단, 판정자 1인·단일 데이터 |
| 과적합 위험 | **중간** — 새 공식을 만든 것은 아니지만, 결과를 보고 기준선을 채택하는 결정 자체가 이 데이터에 맞춘 선택이다 |
| 필요한 새 데이터 | 손대지 않은 데이터셋에서 사전 등록한 동일 비교(현재 AIDA 대 IoU) 재현 |

### B. 계통 유형 승격을 없애거나 상한을 둔다

| | |
|---|---|
| 기대 이득 | 한 유형이 통째로 위를 차지하는 현상(prelim1에서 상위 90 전부 width)을 막는다 |
| 위험 | 승격은 **어긋난 자에서 목록 위를 개선한 실측**(docs/21 AN)에서 왔다. 없애면 그 경우가 나빠질 수 있다. 상한 값은 새로 고르는 손잡이다 |
| prelim1 근거 | 승격 유형 후보 94건 중 오류 4, 비승격 68건 중 14 (사후·선택 편향) |
| 과적합 위험 | **높음** — 상한·문턱 값을 prelim1을 보고 고르면 그대로 이 데이터에 맞춰진다 |
| 필요한 새 데이터 | 손대지 않은 데이터셋 + 절대 문턱·상대 문턱으로 승격이 일어나는 경우를 둘 다 포함하는 설계 |

### C. 데이터셋 수준 진단과 후보 수준 재검수 순위를 분리한다

| | |
|---|---|
| 기대 이득 | "이 데이터셋에 width 오류가 많은 것 같다"는 요약은 유지하고, 후보 순서는 후보 수준 신호로만 정한다. 두 질문을 섞지 않는다 |
| 위험 | 후보 수준 신호가 무엇이어야 하는지 아직 근거가 없다(prelim1에서 심각도는 오류를 위로 올리지 못했다). 설계 변경 범위가 크다 |
| prelim1 근거 | 데이터셋 수준 유형 판정이 후보 전체의 순서를 정했다는 구조적 관찰 |
| 과적합 위험 | **중간** — 구조 분리 자체는 결과와 무관한 원칙이지만, 새 후보 점수를 고르는 단계에서 커진다 |
| 필요한 새 데이터 | 개발 데이터로 설계 → 새 버전 ID 부여 → 손대지 않은 데이터셋에서 사전 등록 비교 |

### D. 개발 데이터로 순위를 보정하거나 학습한다

| | |
|---|---|
| 기대 이득 | 유형·심각도·IoU·신뢰도를 함께 쓰는 순위를 자료로 맞출 수 있다 |
| 위험 | 판정 자료가 작다(오류 18건). 판정자 1인의 기울어짐까지 학습한다. 주입 오류로 맞추면 자연 오류에서 달라진다 |
| prelim1 근거 | 학습 자료로 쓰기엔 너무 작다 |
| 과적합 위험 | **매우 높음** — prelim1이나 같은 계열로 맞추고 같은 계열로 평가하면 그 숫자는 아무것도 보여 주지 않는다 |
| 필요한 새 데이터 | 학습용 개발 판정 자료(여러 판정자 권장)와, 그와 분리된 **손대지 않은 평가용 데이터셋** |

## 3. 어느 안을 고르든 지킬 것

- 바뀐 순위는 **새 버전·설정 ID**를 받는다. 지금의 제품 순서와 같은 이름으로 부르지 않는다.
- prelim1과 그 300장으로 **순위 변경을 검증하지 않는다.** 그 결과를 독립 재현이라 부르지 않는다.
- 새 비교는 **손대지 않은 데이터셋**과 **판정 전에 커밋한 사전 등록**이 있어야 한다.
  N·방법·씨앗·1차 지표·Δ 방침은 결과를 본 뒤 바꾸지 않는다.
- 데이터 경계는 [evaluation-data.md](evaluation-data.md)의 "소비된 개발 데이터" 절.
